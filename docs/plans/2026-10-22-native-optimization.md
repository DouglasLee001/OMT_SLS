Known timing edge (unfixed): acceptance checks the deadline before publishing model.tsv, then copies the incumbent and samples its timestamp. A rename or copy crossing the deadline can replace the old model while the runner rejects the late event. For normal returns, a possible fix is to stage the assignment/value, retain the old model, capture one post-rename commit time, and either restore the old model without updating state/emitting an incumbent when late, or commit with swaps and reuse that timestamp. A post-rename false return alone would lose the old model; clipping/backdating the timestamp would misreport acceptance.

The runner can also terminate the native process between rename and rollback/event emission; native rollback cannot cover that SIGKILL window. Covering it would require a persistent previous-model snapshot and runner recovery matching the accepted objective. Reading model.tsv when consuming an event is insufficient because buffered events may lag newer model publications. No runner/model protocol change or timing fix is claimed in this iteration. The two completed full-run model audits reported zero failures; these edge windows were not observed to invalidate those results.
