# NIA_LS 的 OMT(NIA) 输入与原生优化

现在可以把单目标 OMT(NIA) 的 SMT2 文件转换后，真正读入 NIA_LS 的变量、单项式、文字、子句和独立优化目标中。默认使用 Z3 预处理，原来的 SMT 可行性输入通道保留。

现在支持三个显式模式：`--import-only` 只检查输入；`--first-solution` 使用原有初始化与局部搜索，找到首个可行解立即退出；`--optimize` 在找到可行解后继续改进目标。可选 `--prove-optimal` 在目标停滞后调用 Z3 检查严格改善条件，独立确认有限最优；`--prove-unbounded` 保留原有无界检测。不指定模式时仍明确报错。

## 停滞后独立确认最优：原型

使用 Slurm 分到 server、node1、node2 时，将下方入口换成
`./script/run_optimize_slurm.sh`，`--jobs 180` 表示每台 180 并发，合计最多 540。
提交方式、92 例纯搜索对照和结果目录见 [Slurm 运行说明](../script/README.md#slurm-三节点运行-nia_ls)。

```bash
cd /home/lbh/OMT
./script/run_optimize.sh all --subset all \
  --prove-optimal --optimality-stall 50 --optimality-timeout 30 \
  --prove-unbounded --large-target 1000000 \
  --jobs 180 --timeout 1200
```

本模式不使用对手给出的最优值提前结束，也不因与对手值相等就标记最优。
NIA_LS 找到可行解后，如果连续 50 秒目标没有改善，就对原始 SMT 文件的完整硬约束
加入严格改善条件：最大化为 `obj > best`，最小化为 `obj < best`。
调用的是 Z3 的普通 SMT `check`，不调用 Z3 优化。
返回 `unsat` 才设置 `is_optimal=true` 并停止；`sat`、`unknown`、错误或超时不证明最优，
继续原搜索。SAT 时提取原模型，补全预处理产生的 native 辅助变量，经过 GMP
完整约束和目标校验后更新最好解，并让局部搜索从该模型继续。

`--optimality-timeout 30` 现在表示首次检查预算。检查未完成证明后回到 SLS：
再连续 50 秒没有改善，下一次预算翻倍，例如 `30 → 60 → 120` 秒；如果这段 SLS
找到了更好值，下一次预算改为上一轮的一半，并从新最好值重新等待 50 秒。
同一段 SLS 的多次改善只减半一次，SAT 回灌也算改善；首次检查前的改善保留初始预算。
同一个最好值允许多轮检查。默认预算下限 1 秒（初始预算不足 1 秒时取初始值），
实际预算受本例剩余时间限制；转换、搜索和检查共用 1200 秒。
默认未开启 `--optimality-resume` 时，每次检查使用新的子进程，到期终止并回收后回到 SLS。
`--prove-optimal` 默认关闭，原来的无界证明可以同时启用。初始检查时长、停滞阈值和
SLS 窗口均可调整；上方给出已完成全量对照的推荐配置。

2026-10-26 新增以下可选设置，均在 `--prove-optimal` 下使用：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--optimality-resume` | 关闭 | 同一最好值暂停、恢复同一个 Z3 worker；目标改善后重建查询。 |
| `--optimality-search-window` | `0` | `0` 保留上面的自适应预算；正值指定首次未证后留给 SLS 的连续窗口。 |
| `--initial-z3-after` | `0` | `0` 关闭；正值允许仍无初解时，在达到该时间后的调度检查点调用一次原式 SAT 查询。 |
| `--initial-z3-timeout` | `120` | 上述初解查询的最大预算，实际不超过本例剩余时间。 |

例如，在上方命令后加 `--optimality-resume`，同一目标检查到期后会发送 `SIGSTOP`，
通过 `waitpid` 确认 worker 已停止，再运行 SLS；下次发送 `SIGCONT` 继续原查询，
保留其 Z3 context 和搜索状态。新最好值经过验证后，先终止并回收旧 worker，
下次按新严格界建立查询。worker 配置父进程死亡信号，父进程异常退出或被单独
`SIGKILL` 时，暂停的 worker 也会被清理。

正值 `--optimality-search-window W` 保留首次短检查。短检查返回 `budget/unknown` 后，
先给 SLS 连续 `W` 秒；若没有改善，再尝试较长检查，其预算最多取剩余时间的 98%。
窗口内一旦改善，会重置停滞时钟并恢复短检查。这与是否保留 Z3 worker 分开控制；
`--optimality-resume` 可与零窗口或正窗口组合。

可选 `--initial-z3-after 300 --initial-z3-timeout 120` 在仍无初解时尝试完整原式，
不添加目标界。SAT 模型经过源硬约束、完整 native 子句和目标验证后，作为
`origin=z3_initial` 的普通可行解交给 SLS；SAT 或该查询的 UNSAT 都不会直接产生 A2。
这组数值已用于上方完整实验，仍需显式开启，未设为默认配置。本次只调整 Z3 调度、模型接纳和记录，
原 SLS 算法与原问题硬约束保持原有定义。

结果自动存到 `/data/shared/lbh/OMT/result/NIA_<时间戳>/`，并在同目录生成比较报告。
每例的 `cases/<实例编号>/optimality.smt2` 保存最近一次实际查询，可用 Z3 重查。
原始 CSV 记录检查次数、总检查耗时、状态及 `time_to_optimality_seconds`。
`optimality_schedule` 区分 `adaptive_v1`、`windowed_v1` 与 `persistent_v1`；
`optimality_resume`、窗口设置、下次预算和 SAT 模型接纳数一并记录，并核对配置一致性。
原生 final 还记录 worker 新建与恢复次数，供检查同值续跑是否实际发生。
模型输出保留上一代文件，并在 incumbent 事件中标记 `model_inode`；批处理在进程结束后
按最后一个预算内接纳事件恢复对应模型，避免截止时刻文件先覆盖、事件尚未发布造成错配。
四列结果中的有限目标时间仍为找到该最好值的时间；证明完成时间单独记录。
本模式的 `A2` 只表示本轮 Z3 严格改善查询返回 UNSAT，旧实验仍按原口径解释。

原生调用示例（须保留中间文件 `SOURCE` 指向的原始 SMT2）：

```bash
NIA_LS/src/nia_ls input.nia --optimize --timeout=1200 \
  --prove-optimal --optimality-stall=50 --optimality-timeout=30 \
  --optimality-query-output=optimality.smt2 --model-output=model.tsv
```

省略查询输出路径时，原生程序默认写 `input.nia.optimality.smt2`。
实现与可靠性边界见 [实现细节.md](实现细节.md) 第 15、16 节；后续 UNSAT 策略与
局部搜索信息引导的想法见 [待实现idea.md](待实现idea.md)。

## 优化改动概述

v8 已具备以下主要机制：

- **分阶段搜索**：新增 `--optimize` 入口。在没有可行解时，以可行性为目标，
  保留原首解搜索的状态并交错执行原生精确探索；找到可行解后切换到目标改进。
  主要代码为 `src/nia_omt_optimize.cpp` 和 `src/nia_omt_feasibility.*`。
- **可行解上的目标改进**：增加整数临界点、二次函数顶点、变量联合移动、
  几何步长以及沿已接受方向的放大；允许目标不变但减少改进阻碍的可行中性移动。
  识别到的定义等式和差分约束可联动修复相关变量，候选仍须满足完整硬约束。
- **扰动与严格界修复**：单独保存最好可行赋值，临时工作状态允许不可行。
  取得可行解后，按时间片用自己的最好值建立严格改进约束并执行限时原生修复；切片之间保留
  搜索状态，得到新的自身最好值后再更新严格界。主要代码为 `src/nia_omt_repair.*`。
- **精确验收与结果记录**：接受新最好解前，用 GMP 重新计算全部硬约束和目标，
  输出目标值及找到它的时间，并保存最好模型。历史对手值只用于达到更好结果后
  提前停止，不进入候选生成、搜索打分或严格界构造；严格界来自自己的可行解。

当前 v15 还包含后续加入的扩展，相关收益按各自实验记录：

- **联合分支与固定因子修复**：切换析取分支以联合移动变量；固定一组非线性
  因子后构造保留全部原生硬约束和自身严格界的线性子问题，调用本项目的
  `LiaSolver` 修复。使用 Z3 的表达式容器，不调用 Z3/OptiMathSAT 的求解器来
  优化。主要代码为 `src/nia_omt_disjunctive.h`、`src/nia_omt_bilinear.*`。
- **条件辅助量与搜索坐标**：识别唯一、无环的常量条件定义，输入变化后联动
  更新受影响的辅助量；仅从主要搜索坐标中排除这些可确定的辅助量，完整原生变量和约束仍保留。
  歧义、循环及超出工作上限的情况保守处理，最终仍由完整校验决定是否接受。
- **算术与探索改进**：部分优化续跑增加固定宽度溢出检查，检测到溢出时结束
  该次续跑，由 GMP 主搜索继续探索；为宽域变量增加零值、自身最好赋值附近的
  几何探测，以及独立的修复随机状态。
  搜索中的距离评分可以是近似值，最终可行性和目标验收使用精确整数计算。

每次运行只新增 `result/initial/<时间戳>/results.csv`，原有实验结果保留。字段为源文件、类别、状态、初始目标值、首解耗时和错误说明。`sat` 表示模型经精确校验，`unsat` 仅表示预处理得到矛盾；`unknown`、`timeout`、`error` 都不代表不可满足。错误和进程被终止会如实记录，缺少初解时目标值与首解耗时为空。

单例也可以分开执行：

```bash

NIA_LS/src/nia_ls /tmp/input.nia --first-solution --timeout=1200 --model-output=/tmp/model.tsv
```

原有渐进初始化已支持新格式；初始化没能得到完整可行模型时，保留部分候选交给现有局部搜索。模型来自初始化或局部搜索都要通过独立的 GMP 任意精度整数校验：重新计算每个硬子句和目标，不信任搜索的增量缓存。模型有效时输出 `status=sat`、`model_validated=true`、精确十进制 `objective_value` 和 `is_optimal=false`。返回的目标值允许超过 128 位。候选不满足硬约束时报告 `error`，不会误记为初始解。可选 TSV 文件记录预处理后现存变量的完整赋值，并不重构所有已消元原变量。

局部搜索内部仍沿用固定宽度计算及周期性计时检查，因此严格总时限由批处理脚本保证。单例的 `--timeout` 是内部预算；需要严格截止时，使用批处理入口（也支持 `--input input.smt2` 只运行一例）。

## 如何保住优化目标

不能只把硬约束送进可满足性预处理。例如：

```smt2
(assert (= cost (* x x)))
(minimize cost)
```

如果预处理只看到约束，就可能消掉 `cost`。本实现参考本地 Z3 自身的 Optimize 实现，在预处理前加入一个全新的 `Int -> Bool` 标记函数：

```text
硬约束 ∧ marker(cost)
    ↓ simplify / propagate-values / solve-eqs / simplify / elim-term-ite / simplify
改写后的硬约束 ∧ marker(x*x)
```

这个标记只用于携带目标；其解释可自由选择为真，不限制原问题的整数赋值。预处理结束后，提取标记的唯一参数作为新目标，再移除标记，只把硬约束转为 CNF。这样仍然可以利用等式消元，且优化 `cost` 与优化改写后的 `x*x` 的可行目标值相同。若约束固定 `x=7`，目标会正确成为常数 `49`。

每一阶段都会检查标记恰好保留一次；无法确认时明确拒绝转换。直接发现矛盾时使用不可满足状态和空子句，保留原目标文本；此时中间文件中的数值目标置零，因为没有可行赋值。

方向单独保存为 `min` / `max`，不会把 maximize 的负号弄反。仅在目标中出现的自由变量也会保存。目标中的 ITE 通过新整数变量及定义约束消除。复杂乘积可能引入精确的辅助整数等式，避免直接分配展开后的巨大多项式；这些等式保留在硬约束中。

前端仅调用统一的 Z3 5.1.0 Python SDK 解析器与 tactic，不调用 `Solver.check()` 或
`Optimize.check()`。只在转换 tactic 上设置 `factor_nonlinear=False`，不依赖旧的
`converter/z3_fork`；冻结实验使用随实验复制的 `converter/z3-5.1.0/build`。
原生端执行 SMT 证明与模型恢复时使用同一5.1库的默认参数。

## 原生数据结构

新格式使用独立读取器 `src/nia_omt_input.cpp`，绕过旧 `build_lits()` 和 `build_instance()` 的再次消元、浮点边界计算与系数截断。硬边界保留为约束，不会转换为近似数值边界。

- 变量的整数/布尔类型和名称进入 `_vars` / `name2var`；被预处理消掉的原变量不保证仍存在。
- 整数单项式进入 `_terms`，约束进入 `_lits` / `_clauses`，并构建变量、文字、子句和单项式之间的索引。
- `omt_direction` 保存优化方向，`omt_objective_constant` 与 `omt_objective_terms` 保存改写后的目标。目标项直接引用同一 `_terms` 和最终变量编号。
- `omt_original_objective` 保存原始目标文本，`omt_source` 保存源文件路径。中间变量表保留现存变量名称；这不是对所有已消元原变量的完整模型重构。
- `evaluate_omt_objective(assignment, value, error)` 可以在原生变量赋值上计算目标；乘法、幂和求和都检查溢出。

旧字段 `best_found_cost` 仍表示未满足硬子句的数量，不是 OMT 的目标值。优化模式从上述 `omt_*` 字段读取实际目标，并以 GMP 任意精度整数计算约束和目标；只有满足全部硬约束的赋值才能更新最好记录。

所有输入系数、常数和目标系数按十进制精确读取到 signed `__int128`，超范围明确报错。支持大于 10000000 的系数及 4、5 次和更高次的项，不再套用旧解析器的限制。多项式求值仍受 128 位中间运算范围限制。现有局部搜索的默认变量边界和部分计算逻辑仍需在实现 OMT 优化搜索时进一步处理；导入检查不以这些默认边界削弱逻辑约束，也不启动搜索。首解模式会使用现有搜索，但报告可行解前额外用 GMP 校验原生硬约束和计算目标。

## 中间格式 `NIA_LS_OMT 1`

文本按空白分隔，名称、路径、原始目标用 UTF-8 的十六进制编码，`-` 代表允许为空的文本。变量编号从 0 开始，文字编号从 1 开始，声明必须按编号递增。SMT2 源文件不被修改。

```text
NIA_LS_OMT 1
STATUS ready
SOURCE <路径的UTF8hex>
ORIGINAL_OBJECTIVE <原目标的UTF8hex>
DIRECTION min
VARIABLES N
0 I <变量名的UTF8hex>
...
LITERALS M
1 B <布尔变量编号>
2 L <常数> <项数>
<系数> <因子数> <变量编号> <正整数指数> ...
...
CLAUSES C
<子句长度> <带符号的文字编号> ...
...
OBJECTIVE <常数> <项数>
<系数> <因子数> <变量编号> <正整数指数> ...
...
END
```

变量类型 `I` 为整数，`B` 为布尔；整数文字的 `L` 表示 `常数 + Σ(系数 × 单项式) <= 0`，`E` 表示同一多项式等于零。严格整数不等式用加一精确转换。子句中的负编号表示文字的逻辑否定。目标采用相同多项式表示。读取器检查格式版本、类型、编号、系数范围、完整性与尾部垃圾，错误时返回非零退出码。

目前支持一个非增量的整数优化目标，以及 QF_NIA 的整数多项式、布尔组合和 ITE；多目标、量词、Real、位向量、一般 UF、div/mod 等输入明确拒绝，不会当作转换成功。

## 原生优化模式（2026-10-22）

结果和版本区别见前面的“当前优化结果总结”。以下说明具体实现与运行方式；
末尾折叠保留开发与验证记录，其中 379 例要求及 80% 可达性诊断属于先前目标，
相关诊断已停止。

`src/nia_omt_optimize.cpp` 在已有首解模式之外增加 `--optimize`。原有
`--first-solution` 的搜索流程保留。优化模式先调用现有初始化和局部搜索寻找
可行解；尚未找到时继续交错执行首解搜索与原生探索，有可行解后再进行目标改进。
搜索在原生 NIA_LS 数据结构上执行，没有调用 Z3/OptiMathSAT 的优化器。

优化阶段保存独立的最好可行赋值，当前搜索状态允许暂时不可行。候选邻域包括
单变量临界值、整数二次函数顶点、两变量交换、等式定义的联动修复，以及目标变量
和分支布尔变量的联合扰动。大整数目标可以通过几何步长改进。识别到的定义等式
及唯一无环的条件定义可联动更新辅助变量，投影受工作上限限制。优化主搜索中的
多项式真值和目标值使用 GMP 增量计算，距离评分可用近似值；接受并输出新最好解前，
再从完整赋值独立重算所有硬约束及目标，不依赖搜索缓存。取得可行解后，
`src/nia_omt_repair.cpp` 按时间片从**自己的当前最好值**建立严格改进约束，
在单独的原生搜索状态内做限时修复。
此可选修复对不支持的大系数/常数会跳过。变量赋值沿用有符号
128 位整数；在优化主搜索和最终验收中，约束值、幂和目标值由 GMP 精确计算。

每个新最好解输出并刷新一条 JSONL，记录原目标方向、精确整数值和已用时间。
最好模型通过临时文件和原子替换保存。`--target=<整数>` 仅用于“严格超过该值后
停止”的判断，不参与候选生成、约束构造、初始化或搜索打分。没有最优性证明时
始终输出 `is_optimal=false`，超时前已校验的可行解仍会保留。

会记录所选 subset。

不会声称无界或自动结束优化。新功能默认关闭。在此前被 bounded 规则排除的

`excluded` 是完整历史 CSV 与 bounded CSV 的差集，并非已证明无界集合。

可选的无界证明模式在本求解器找到大目标可行解之后，选取当前满足且覆盖全部硬
子句的文字，固定部分变量转成 LIA，调用已链接的 Z3 寻找整数增长方向。方向经过
GMP 精确验算才报告无界，并立即结束该实例；未找到证明时继续原优化。

`--prove-unbounded` 默认关闭；启动阈值默认最大化 `obj >= 1000000`、最小化
`obj <= -1000000`，可用 `--unbounded-threshold M` 调整。它与 `--large-target`
独立：前者决定何时尝试证明，后者决定额外搜索的有限目标。每实例先尝试一次，
内部最多尝试八种固定方案，本地调度预算为 `min(5 秒, 原生时间限的 5%)`，计入总时间。
预算在检查点生效，实际耗时包含整数运算和调度延迟；证明仍须在本例总截止时间内完成。
证明模式自动关闭历史 strict-win 早停，仍允许匹配对手已证最优值时提前结束。
