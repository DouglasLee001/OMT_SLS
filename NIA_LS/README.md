# NIA_LS 的 OMT(NIA) 输入与原生优化

现在可以把单目标 OMT(NIA) 的 SMT2 文件转换后，真正读入 NIA_LS 的变量、单项式、文字、子句和独立优化目标中。默认使用 Z3 预处理，原来的 SMT 可行性输入通道保留。

现在支持三个显式模式：`--import-only` 只检查输入；`--first-solution` 使用原有初始化与局部搜索，找到首个可行解立即退出；`--optimize` 在找到可行解后继续改进目标。优化模式的步骤与实验结果见下文，当前不提供最优性证明。不指定模式时仍明确报错。

## 优化改动概述

v8 已具备以下主要机制：

- **分阶段搜索**：新增 `--optimize` 入口。在没有可行解时，以可行性为目标，
  保留原首解搜索的状态并交错执行原生精确探索；找到可行解后切换到目标改进。
  主要代码为 `src/nia_omt_optimize.cpp` 和 `src/nia_omt_feasibility.*`。
- **可行解上的目标改进**：增加整数临界点、二次函数顶点、变量联合移动、
  几何步长以及沿已接受方向的放大；允许目标不变但减少改进阻碍的可行中性移动。
  识别到的定义等式和差分约束可联动修复相关变量，候选仍须满足完整硬约束。
- **扰动与严格界修复**：单独保存最好可行赋值，临时工作状态允许不可行。
  取得可行解后，按时间片用自己的最好值建立严格改进约束并执行限时原生修复；切片之间保留
  搜索状态，得到新的自身最好值后再更新严格界。主要代码为 `src/nia_omt_repair.*`。
- **精确验收与结果记录**：接受新最好解前，用 GMP 重新计算全部硬约束和目标，
  输出目标值及找到它的时间，并保存最好模型。历史对手值只用于达到更好结果后
  提前停止，不进入候选生成、搜索打分或严格界构造；严格界来自自己的可行解。

当前 v15 还包含后续加入的扩展，相关收益按各自实验记录：

- **联合分支与固定因子修复**：切换析取分支以联合移动变量；固定一组非线性
  因子后构造保留全部原生硬约束和自身严格界的线性子问题，调用本项目的
  `LiaSolver` 修复。使用 Z3 的表达式容器，不调用 Z3/OptiMathSAT 的求解器来
  优化。主要代码为 `src/nia_omt_disjunctive.h`、`src/nia_omt_bilinear.*`。
- **条件辅助量与搜索坐标**：识别唯一、无环的常量条件定义，输入变化后联动
  更新受影响的辅助量；仅从主要搜索坐标中排除这些可确定的辅助量，完整原生变量和约束仍保留。
  歧义、循环及超出工作上限的情况保守处理，最终仍由完整校验决定是否接受。
- **算术与探索改进**：部分优化续跑增加固定宽度溢出检查，检测到溢出时结束
  该次续跑，由 GMP 主搜索继续探索；为宽域变量增加零值、自身最好赋值附近的
  几何探测，以及独立的修复随机状态。
  搜索中的距离评分可以是近似值，最终可行性和目标验收使用精确整数计算。

单例也可以分开执行：

```bash
python3 NIA_LS/converter/omt_to_ls.py input.smt2 -o /tmp/input.nia
NIA_LS/src/nia_ls /tmp/input.nia --first-solution --timeout=1200 --model-output=/tmp/model.tsv
```

## 如何保住优化目标

不能只把硬约束送进可满足性预处理。例如：

```smt2
(assert (= cost (* x x)))
(minimize cost)
```

如果预处理只看到约束，就可能消掉 `cost`。本实现参考本地 Z3 自身的 Optimize 实现，在预处理前加入一个全新的 `Int -> Bool` 标记函数：

```text
硬约束 ∧ marker(cost)
    ↓ simplify / propagate-values / solve-eqs / simplify / elim-term-ite / simplify
改写后的硬约束 ∧ marker(x*x)
```

这个标记只用于携带目标；其解释可自由选择为真，不限制原问题的整数赋值。预处理结束后，提取标记的唯一参数作为新目标，再移除标记，只把硬约束转为 CNF。这样仍然可以利用等式消元，且优化 `cost` 与优化改写后的 `x*x` 的可行目标值相同。若约束固定 `x=7`，目标会正确成为常数 `49`。

每一阶段都会检查标记恰好保留一次；无法确认时明确拒绝转换。直接发现矛盾时使用不可满足状态和空子句，保留原目标文本；此时中间文件中的数值目标置零，因为没有可行赋值。

方向单独保存为 `min` / `max`，不会把 maximize 的负号弄反。仅在目标中出现的自由变量也会保存。目标中的 ITE 通过新整数变量及定义约束消除。复杂乘积可能引入精确的辅助整数等式，避免直接分配展开后的巨大多项式；这些等式保留在硬约束中。

前端仅调用 `converter/z3_fork` 的 Python SDK 解析器与 tactic，不调用该 fork 的 `Solver.check()` 或 `Optimize.check()`，也不走其原有的 SMT 求解后打印路径。用户已有的 `qfnia_tactic.cpp` 修改保留。

## 原生数据结构

新格式使用独立读取器 `src/nia_omt_input.cpp`，绕过旧 `build_lits()` 和 `build_instance()` 的再次消元、浮点边界计算与系数截断。硬边界保留为约束，不会转换为近似数值边界。

- 变量的整数/布尔类型和名称进入 `_vars` / `name2var`；被预处理消掉的原变量不保证仍存在。
- 整数单项式进入 `_terms`，约束进入 `_lits` / `_clauses`，并构建变量、文字、子句和单项式之间的索引。
- `omt_direction` 保存优化方向，`omt_objective_constant` 与 `omt_objective_terms` 保存改写后的目标。目标项直接引用同一 `_terms` 和最终变量编号。
- `omt_original_objective` 保存原始目标文本，`omt_source` 保存源文件路径。中间变量表保留现存变量名称；这不是对所有已消元原变量的完整模型重构。
- `evaluate_omt_objective(assignment, value, error)` 可以在原生变量赋值上计算目标；乘法、幂和求和都检查溢出。

旧字段 `best_found_cost` 仍表示未满足硬子句的数量，不是 OMT 的目标值。优化模式从上述 `omt_*` 字段读取实际目标，并以 GMP 任意精度整数计算约束和目标；只有满足全部硬约束的赋值才能更新最好记录。

所有输入系数、常数和目标系数按十进制精确读取到 signed `__int128`，超范围明确报错。支持大于 10000000 的系数及 4、5 次和更高次的项，不再套用旧解析器的限制。多项式求值仍受 128 位中间运算范围限制。现有局部搜索的默认变量边界和部分计算逻辑仍需在实现 OMT 优化搜索时进一步处理；导入检查不以这些默认边界削弱逻辑约束，也不启动搜索。首解模式会使用现有搜索，但报告可行解前额外用 GMP 校验原生硬约束和计算目标。

## 中间格式 `NIA_LS_OMT 1`

文本按空白分隔，名称、路径、原始目标用 UTF-8 的十六进制编码，`-` 代表允许为空的文本。变量编号从 0 开始，文字编号从 1 开始，声明必须按编号递增。SMT2 源文件不被修改。

```text
NIA_LS_OMT 1
STATUS ready
SOURCE <路径的UTF8hex>
ORIGINAL_OBJECTIVE <原目标的UTF8hex>
DIRECTION min
VARIABLES N
0 I <变量名的UTF8hex>
...
LITERALS M
1 B <布尔变量编号>
2 L <常数> <项数>
<系数> <因子数> <变量编号> <正整数指数> ...
...
CLAUSES C
<子句长度> <带符号的文字编号> ...
...
OBJECTIVE <常数> <项数>
<系数> <因子数> <变量编号> <正整数指数> ...
...
END
```

变量类型 `I` 为整数，`B` 为布尔；整数文字的 `L` 表示 `常数 + Σ(系数 × 单项式) <= 0`，`E` 表示同一多项式等于零。严格整数不等式用加一精确转换。子句中的负编号表示文字的逻辑否定。目标采用相同多项式表示。读取器检查格式版本、类型、编号、系数范围、完整性与尾部垃圾，错误时返回非零退出码。

目前支持一个非增量的整数优化目标，以及 QF_NIA 的整数多项式、布尔组合和 ITE；多目标、量词、Real、位向量、一般 UF、div/mod 等输入明确拒绝，不会当作转换成功。

## 原生优化模式（2026-10-22）

结果和版本区别见前面的“当前优化结果总结”。以下说明具体实现与运行方式；
末尾折叠保留开发与验证记录，其中 379 例要求及 80% 可达性诊断属于先前目标，

`src/nia_omt_optimize.cpp` 在已有首解模式之外增加 `--optimize`。原有
`--first-solution` 的搜索流程保留。优化模式先调用现有初始化和局部搜索寻找
可行解；尚未找到时继续交错执行首解搜索与原生探索，有可行解后再进行目标改进。
搜索在原生 NIA_LS 数据结构上执行，没有调用 Z3/OptiMathSAT 的优化器。

优化阶段保存独立的最好可行赋值，当前搜索状态允许暂时不可行。候选邻域包括
单变量临界值、整数二次函数顶点、两变量交换、等式定义的联动修复，以及目标变量
和分支布尔变量的联合扰动。大整数目标可以通过几何步长改进。识别到的定义等式
及唯一无环的条件定义可联动更新辅助变量，投影受工作上限限制。优化主搜索中的
多项式真值和目标值使用 GMP 增量计算，距离评分可用近似值；接受并输出新最好解前，
再从完整赋值独立重算所有硬约束及目标，不依赖搜索缓存。取得可行解后，
`src/nia_omt_repair.cpp` 按时间片从**自己的当前最好值**建立严格改进约束，
在单独的原生搜索状态内做限时修复。
此可选修复对不支持的大系数/常数会跳过。变量赋值沿用有符号
128 位整数；在优化主搜索和最终验收中，约束值、幂和目标值由 GMP 精确计算。

每个新最好解输出并刷新一条 JSONL，记录原目标方向、精确整数值和已用时间。
最好模型通过临时文件和原子替换保存。`--target=<整数>` 仅用于“严格超过该值后
停止”的判断，不参与候选生成、约束构造、初始化或搜索打分。没有最优性证明时
始终输出 `is_optimal=false`，超时前已校验的可行解仍会保留。

**默认启用“达到对手已证明最优值后停止”，即使指定 `--no-target` 也保留此规则。**

不足以启用此规则。若两个对手的已证明值不一致，或另一个历史可行值已经严格
更好，则该实例禁用此规则。

不是 NIA_LS 自行生成最优性证明，原生 `is_optimal` 字段仍为 `false`。
