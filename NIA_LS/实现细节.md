# NIA_LS 的 OMT(NIA) 实现细节

本文说明当前 NIA_LS 在 OMT(NIA) 上已经实现的处理。核心流程是：先寻找满足全部
硬约束的可行解，再改进目标；遇到阻碍时，允许扰动当前状态，通过修复寻找更好的
可行解。整个过程中单独保存已经验证的最好解。

原生优化部分对应当前 v15 源码；批处理部分还包括后续加入的完整 bounded
集合选择与“达到对手已证明最优值后停止”规则。
在此基础上，新增了默认关闭的有限大目标探测，见第 13 节。

## 1. 问题表示与整体流程

一个实例包含硬约束 `H(x)`、整数目标 `F(x)` 和优化方向 `min` 或 `max`。
优化目标是在满足 `H(x)` 的前提下，使 `F(x)` 尽可能小或尽可能大。

硬约束与目标使用相同的原生变量和单项式，但目标单独存储：

```text
SMT2 文件：硬约束 + minimize/maximize
    ↓ Z3 解析、目标保护和预处理
NIA_LS_OMT 中间格式：变量、单项式、文字、子句、优化方向、目标
    ↓ 原生读取
寻找初始可行解
    ↓ 找到可行解
可行邻域改进 / 中性移动 / 联动修复
    ↔ 扰动后的不可行状态与修复搜索
    ↓ 完整精确校验
保存新的最好可行解及找到它的时间
```

Z3 承担前端解析和预处理。优化搜索使用 NIA_LS 的原生数据结构与搜索模块。
局部搜索本身是有时间预算的启发式搜索。新增可选的有限最优性 SMT 检查见第 15 节，
它使用 Z3 的 UNSAT 结论确认最优，不是局部搜索本身生成的证明。

## 2. 输入转换：允许消元，但保住改写后的目标

### 2.1 为什么需要单独保护目标

直接预处理硬约束时，目标变量可能被等式消元。例如：

```smt2
(assert (= cost (* x x)))
(minimize cost)
```

硬约束预处理后，`cost` 可能不再出现在剩余变量中。转换器需要保留的是与原目标
等价的表达式，例如 `x*x`，不要求原变量名 `cost` 始终存在。

### 2.2 使用新鲜标记携带目标

转换器引入一个全新的 `Int -> Bool` 标记函数，把目标放进同一个预处理过程：

```text
硬约束 ∧ marker(cost)
    ↓ simplify / propagate-values / solve-eqs / elim-term-ite 等处理
改写后的硬约束 ∧ marker(x*x)
```

标记函数没有其他用途，其解释可以取为恒真，因此不额外限制原问题的整数赋值。
每个相关阶段检查目标标记是否唯一保留；提取改写后的参数后移除标记，再把硬约束
转为 CNF。标记丢失或重复时明确拒绝转换。

优化方向单独记录，避免最大化目标的符号处理混淆。原始目标文本作为元数据保留，
实际搜索与计值使用改写后的目标。目标中的 ITE 和复杂乘积可以引入辅助变量，
相应定义保留在硬约束中。

### 2.3 原生输入结构

`NIA_LS_OMT 1` 分别记录变量、文字、子句、目标常数与目标项。读取器直接构建
原生索引，避免旧输入路径再次消元、浮点边界换算或系数截断。原有
`best_found_cost` 仍表示未满足硬子句数，实际 OMT 目标由独立的 `omt_*` 字段保存。

目前支持单个非增量整数优化目标及整数多项式、布尔组合、ITE。多目标、量词、
Real、一般 UF、div/mod 等未支持的输入明确拒绝。

对于 Leipzig，批处理转换采用限定的 `--keep-definitions` 策略，保留低次辅助
定义，减少反复代入引起的高次多项式膨胀；其他来源保留默认转换参数。

## 3. 搜索状态：最好解与当前工作状态分开

优化器维护三个相关但不同的状态：

| 状态 | 含义 | 是否允许违反硬约束 |
| --- | --- | --- |
| 当前工作赋值 `state.x` | 用于移动、扰动和修复的探索位置 | 允许 |
| 最好可行赋值 `best` | 已完整校验、目标值最好的已公布结果 | 不允许 |
| 可行代表 `feasible_representative` | 用于继续探索的同目标值可行状态，可承接中性移动 | 不允许 |

暂时破坏当前赋值不会覆盖最好解。只有候选满足全部硬约束，且原目标值严格改善，
才更新最好记录。最小化时要求新值更小，最大化时要求新值更大。

可行中性移动可以更新工作状态和可行代表，但不刷新“找到最好值的时间”。

## 4. 阶段一：优先寻找初始可行解

没有最好可行解时，搜索首先处理违反的硬约束，而不是把不可行状态的目标值当作
有效优化结果。

初始化尝试提供一个完整或部分赋值。已有可行性搜索被封装为可暂停、恢复的
`OmtFeasibilityContinuation`，保留搜索轨迹、缓存、重启状态和独立随机状态。
切片结束后继续原轨迹，避免每次重新初始化、重复搜索同一个前缀。

在初始可行性尝试后，如果仍未获解，就交错执行可行性续跑和原生探索。当前调度
中，初次可行性续跑最多分配约 60 秒且受剩余预算比例限制，后续以约 5 秒切片
继续，中间穿插原生探索。它不会因为最初一段时间没找到解就彻底丢弃首解搜索。

初次可行性续跑可以保留已有的启发式算术路径，产生的赋值只是候选。发布之前仍
须通过完整 GMP 校验；被拒收的候选不能进入最好结果。

## 5. 阶段二：在可行解附近改进目标

### 5.1 面向目标的候选邻域

普通改进步骤优先选择仍满足全部硬约束、并改善当前目标值的候选。邻域包括：

- 单变量局部步长、整数临界点附近值和允许范围端点。
- 二次目标的顶点附近整数，以及投影后目标的二次拟合候选；拟合结果也只作为候选。
- 两变量交换或联合移动，跨过单变量无法改善的状态。
- 面向目标的联合探针，以及目标变量与相关布尔分支的联合变化。
- 宽域变量上的零值和自身最好赋值附近的几何步长探测。

若已经发生一次成功改进，优化器还会沿前后两次已接受赋值的完整差向量作几何
放大，同时重新投影识别到的定义。这可以一次推动多个必须同向变化的坐标。

所有候选都要重新检查约束；二次拟合、外推方向或局部评分本身不保证有效。

### 5.2 可行中性移动

有时必须先改变布局，下一步才有机会降低目标。实现允许在保持可行和目标值不变
的情况下移动，但要求针对目标改进探针的阻碍度严格下降。

中性阶段设有步数上限，并保存同目标值的可行代表，减少平台上的重复往返。
它不发布一个新的最好目标值，也不改变已有最好值的发现时间。

## 6. 阶段三：扰动、修复与自身严格改进界

### 6.1 允许探索暂时不可行的状态

停滞时，优化器可以扰动工作赋值、改变部分目标坐标或分支，再进入修复过程。
最好可行解始终单独保留。

不可行阶段的候选排序使用未满足子句的加权代价和距离等启发式信息；已有最好解
时，还对没有严格改善该值的状态施加虚拟严格界惩罚。约束真值与目标值使用精确
整数，距离与排序中的部分启发式量使用浮点数。

### 6.2 把改进任务转成一个新的可行性任务

假设自己的当前最好目标值为整数 `B`，严格改进条件为：

```text
最小化：H(x) ∧ F(x) <= B - 1
最大化：H(x) ∧ F(x) >= B + 1
```

由于目标是整数，可以用加减一精确表达严格不等式。
`OmtBoundRepair` 重新读入完整原生硬约束，在独立副本上增加这个条件，再用自己的
最好赋值作为修复起点。该条件不写回原始 benchmark。

取得可行解后，这类修复按时间片定期调度。只要自己的最好值不变，修复对象就
继续保存和恢复；最好值改变后，再构造对应的新严格界。修复返回的模型必须同时
通过原约束与严格改进条件的精确检查。

严格界来自 NIA_LS 自己的已验证可行解。修复失败、超时或不支持当前系数范围，
仅表示这次没有返回改善，不表示已经证明严格界不可满足，也不表示最好解已最优。

## 7. 利用约束结构做联动处理

### 7.1 定义等式与条件辅助量

改变一个输入变量后，相关辅助量可能也需要改变。例如目标或硬约束中包含
`aux = ite(g, a, b)` 时，修改影响 `g` 的变量后，旧的 `aux` 值可能立即失效。

实现识别部分单位等式、带守卫的定义，以及唯一、无环的常量条件定义，沿依赖
关系联动更新辅助量。整数等式的求解需要检查整除性，不把非整数结果直接舍入
成一个声称满足等式的值。

当前 v15 将唯一、无环的常量条件定义输出从主要搜索坐标中排除，并把目标优先级
和修复需求追溯到它们的输入变量。完整原生变量和硬约束仍保留。这样减少直接
扰动可由输入确定的辅助量，而不是删除它们对应的约束。

投影有工作上限。常量条件定义中的循环、歧义及其依赖不做坐标消除；无法处理的
投影跳过。投影只是候选生成手段，最终仍检查全部硬约束。

### 7.2 差分约束与析取分支

对于可识别的整数差分约束，可以在固定改进探针后，联动调整一组变量。基本路径
选择当前满足的差分分支，用 GMP Bellman–Ford 处理；扩展路径还可以尝试替换
析取见证，让多个位置一起重排。

图中负环表示当前这组分支选择存在冲突，不能据此断言整个原问题不可满足。
不支持的约束仍留给完整候选验收。

### 7.3 零乘积平台

对于多个因子同时为零的乘积，只移动一个因子可能仍使乘积为零，无法改善约束。
零乘积联合邻域会尝试同时改变多个因子，再检查完整约束，跨过这种单坐标平台。

### 7.4 固定非线性因子，搜索剩余线性问题

`OmtBilinearRepair` 选择一组变量固定为自己的候选值，使剩余多项式尽量成为线性
表达式。例如固定 `x=a`、`z=b` 后，`x*y + z*z` 可以写成 `a*y + b*b`。

双线性二分图结构可交替固定两侧；后续实现还支持部分一般多项式结构，通过固定
高次变量和选择覆盖集合，保证每项最多留下一个一次幂自由变量。

在线性化后，保留完整 CNF 和自身严格改进界，调用本项目的 `LiaSolver` 搜索。
这里使用 Z3 的表达式与模型容器。修复器在切片间保留工作赋值、覆盖集合尝试
进度、中性移动历史和独立随机状态；每次尝试重新构造 `LiaSolver`。返回候选后，
再对原始原生约束与目标进行 GMP 校验。

固定集合、表达式大小、次数与时间都有上限。不支持的情况跳过这个可选算子，
不通过删掉约束、截断多项式或近似系数来构造一个更容易的问题。

## 8. 数值精度与最好解验收

需要区分存储范围、搜索评分和正确性验收：

| 环节 | 当前处理 |
| --- | --- |
| 输入系数、常数、整数变量赋值 | 有符号 128 位整数，超出支持范围时明确处理 |
| 优化主搜索中的多项式真值与目标 | GMP 任意精度整数计算，支持目标结果超过 128 位 |
| 距离、部分排序启发式 | 可以使用浮点数，只用于选择探索方向 |
| 部分固定宽度续跑 | 加入溢出检查；不能继续时结束该次续跑，主搜索继续探索 |
| 发布最好解前 | 从完整赋值独立重算全部原生硬子句和目标 |

最终验收不信任增量缓存和旧算术评分。布尔赋值也要符合原生表示，候选必须满足
全部硬子句，才有资格更新最好解。实现中的有限存储范围和启发式邻域意味着搜索
不完备；不能把没找到更好解解释为已经证明最优。

## 9. 找到什么条件时停止

三类数值在实现中承担不同角色：

| 数值来源 | 用途 |
| --- | --- |
| 自己当前最好可行值 `B` | 生成严格改进界、引导修复 |
| 对手历史最好值，尚未确认最优 | 可选的“严格超过对手后停止”目标 |
| 对手历史中已标记证明最优的值 `x` | 匹配该值后结束本实例 |

### 9.1 可选的严格胜出停止

原生 `--target=<整数>` 只用于判断是否已严格超过该参考值。
它不参与候选生成、初始化、搜索打分或严格界构造。
批处理的 `--no-target` 关闭这条停止规则。

### 9.2 匹配对手已证明的最优值

批处理读取历史 CSV 中 Z3 和 OptiMathSAT 的最好值及 `is_optimal` 标记。若某个
有限整数值 `x` 已标记为最优，则在 NIA_LS 报出经校验、目标值恰好等于 `x` 的
可行解后，脚本可以结束该实例的进程组，保留模型、值和发现时间，再调度下一例。

两个对手的已证明值不一致，或另一个历史可行值已经更好时，该实例不使用这条
提前停止规则。该规则默认开启，指定 `--no-target` 后仍保留；如需禁用，可使用
`--no-known-optimum-stop`。

脚本先接收有效进度，再中断并清理进程组，读取剩余输出；实际报错、异常退出或
清理时出现的目标值矛盾仍如实记录。实际由这条规则中断的实例记为
`termination=known_optimum_reached`。CSV 另保存：

- `known_optimum_value`：已知最优参照值。
- `known_optimum_source`：提供该值的对手。
- `known_optimum_reached`：本次成功保留的最好解是否匹配参照值。

自然结束但数值匹配时，只将匹配字段记为 `true`，保留自然结束的原因。
这里使用的是对手的历史最优性标记，不重新生成或重放对手的 SMT 最优性证明。
仅凭这种历史值匹配，NIA_LS 原生输出的 `is_optimal` 仍为 `false`。
启用第 15 节的 `--prove-optimal` 时关闭此停止规则，改由本轮严格改善查询确认。

## 10. 时间预算、并行与结果保存

完整 bounded 集合的运行命令为：

```bash
cd /home/lbh/OMT
./script/run_optimize.sh all --subset bounded --jobs 180 --timeout 1200 --no-target
```

该命令读取 original 的 3699 例和 new 的 563 例，共 4262 例。
省略 `--subset bounded` 时，仍选择原来的 473 例 `unsolved_bounded_sol` 子集。

最多同时运行 180 个实例任务，每个任务顺序执行转换和原生求解。每例总预算
1200 秒，包括转换、导入、初始化、搜索和验收；排队与启动前的清单扫描不计入
该例预算。正常搜索使用剩余预算，达到已知最优值、预处理矛盾、错误或没有可搜索
变量时可能提前结束。

运行器使用外部截止时间清理进程组，只接收预算内完成验收与保存的最好解。
最好模型先写临时文件，再原子替换；新的最好值及时刷新到 JSONL 日志。
结果中的“找到最好值的时间”是这次严格改进的发现时间，不是实例最终结束时间。

运行开始时复制求解器可执行文件，并在清单中记录二进制与转换器的 SHA256。
各轮从头运行，不把历史结果模型作为新的初始解。结果目录保存 CSV、运行清单、
原生输入、最好模型和日志，便于后续独立审计。

## 11. 独立验证与实验解释

`script/verify_optimize.py` 用 Python 任意精度整数重新检查保留的最终模型、硬约束、
目标、进度、时间与清单。对于已知最优停止，还独立读回历史 CSV，检查参照值、
来源和原始优化方向。它不把运行器声明的匹配标记直接当作验证结论。

这份检查针对转换后的原生公式，不额外证明整个 SMT2 前端转换的等价性；此前未
保留赋值的中间最好解，也只能检查其记录顺序和时间。

当前完整 bounded 实验共 4262 例，4223 例找到可行解，39 例超时未获初解；
3274 例达到对手已证明的最优值，其中 3273 例由匹配规则提前结束。
在原来的 473 例挑战子集上，本轮严格优于逐例更好对手的数量为 326。
历史 v8 单轮最好记录为 330，属于另一冻结版本和运行，不能将两轮成功实例合并。

本轮记录见 [逐例结果](../result/optimize/20261022-085117-434834/results.csv)
和 [独立验证报告](../result/optimize/20261022-085117-434834/verification.json)。

## 13. 有限大目标探测：最大幅度 2^127-1

### 13.1 这一步尝试什么

这个实验功能处理一种情况：已经有合法可行解，目标也在不断改善，但普通邻域
可能只在局部推进。此时额外提出一个较远的目标，把它转成一次可行性局部搜索。
用户给定正整数幅度 `M`，初版实验值为 `10000000000`，当前实验幅度改为
`2^127-1 = 170141183460469231731687303715884105727`：

```text
最小化：H(x) ∧ F(x) <= -M
最大化：H(x) ∧ F(x) >=  M
```

这里使用包含等号的不等式，不强制目标恰好等于阈值。例如最大化时，若只能取
偶数目标，也允许找到比阈值更大的合法值。硬约束中的乘法、加法、等式和分支
始终按普通整数语义计算；这一步尚未引入抽象无穷值。

找到阈值模型只说明目标能达到这个有限水平，不能证明无界。对于任意有限阈值，
一个有界实例也可能达到它；反之，一次启发式搜索没有达到阈值也不能证明有界。
仅达到有限大目标不设置原生 `is_optimal`；独立最优性检查另见第 15 节。

### 13.2 什么时候启动

功能默认关闭。开启后，调度器只观察已经通过独立精确验收的最好可行值：

1. 先取得第一个可行值 `B0`。
2. 在它之后，至少发布三次严格改善的最好值。
3. 累计改善幅度至少为 `max(100, ceil(abs(B0)/10))`。
4. 当前最好值尚未达到带方向的阈值，并且仍有探测预算。

若普通搜索已经达到阈值，直接记录 `large_target_reached=true`，无需重复启动
探测。因此该字段为真时，`large_target_attempts` 仍可能为零。单纯取得一个
绝对值很大的初解，但没有上述改善过程，不会触发额外搜索。

### 13.3 如何复用局部搜索

有限大目标探测统一使用 `OmtBoundRepair` 的有限阈值构造入口，接收自己的已验证可行
赋值、该赋值的精确目标值和带符号的阈值。原有“自己的最好值加减一”的构造
入口与搜索限制保留。

有限阈值模式重新读入完整原生硬约束，在独立副本中加入目标文字。若目标为
`F=C+sum(a_i*t_i)`，加入的文字分别为：

```text
min： (C - threshold) + sum( a_i*t_i) <= 0
max： (threshold - C) + sum(-a_i*t_i) <= 0
```

构造过程先用 GMP 计算，再检查新增常数和系数能否存入 signed128。新入口的
阈值必须严格优于它收到的自己的最好值；无改善、常数目标没有可搜索项或存储
越界时，返回不支持，让主搜索继续。

原局部搜索有绝对值 `10^8` 的变量动作限制，以及 INT64 的部分长项限制，直接
保留这些限制会阻止尝试 `10^10`。新模式只在私有副本开启 `wide_omt_moves`：
扩大整数变量的搜索范围，跳过上述两个启发式限制，同时保留全部原硬约束。
这个标记仅在精确算术作用域内生效；初始化、动作生成与增量更新继续使用带
溢出检查的整数运算。原求解器、初解搜索和原有严格界修复不因此放宽范围。

私有搜索保留自己的赋值、缓存和随机状态，可以跨时间片续跑。候选返回时，
分别对增广约束和完整原生约束做 GMP 验证，并精确检查目标达到阈值；然后再
经过主优化器的统一验收入口，只有严格改善当前最好值才能发布。失败的探测
不覆盖主搜索的工作状态、最好模型或随机轨迹。

### 13.4 探测预算与数值限制

探测按约 1 秒的时间片运行，两次调度至少间隔 5 秒；总调度配额取每例预算的
5% 和 30 秒中的较小值。计时包括副本构造、续跑与候选验收。切片截止时间也
传入内部重启修复，避免它直接使用整个实例的剩余时间。

读入副本、单次算术操作和完整候选验收不能在中间抢占，可能有一次操作的收尾
超出；配额耗尽后不再启动下一片。整个实例仍受批处理外部 1200 秒总截止时间
约束。成功验收后的正常改进方向外推属于主优化流程。

输入幅度 `M` 必须是正十进制整数，且不超过 `2^127-1`。私有续跑仍受 signed128 中间结果限制，发生溢出时放弃这条探测轨迹；主优化器的 GMP
搜索与已接受模型保留。超时、溢出、不支持和没有找到阈值解均不表示原问题
UNSAT、有界或无界。

### 13.5 运行与结果字段

在此前被 bounded 规则排除的 original 实例上运行：

`--subset excluded` 读取完整历史 CSV 与 bounded CSV 的源文件差集，不移动、

`--no-target` 关闭“严格超过历史最好值就结束”的规则，便于观察持续优化。
匹配对手已证明最优值的停止规则仍保留；如需同时关闭，可另加

### 13.6 为什么排除集不能直接叫已证明无界

旧 bounded 规则按历史最好值的绝对值过滤。2045 个 original 排除项中，2043 个
有向负方向达到大值的历史记录，但双方均未确认最优；另两个 AProVE 例子为：

- `AProVE/aproveSMT2000554635680853132@4.smt2`
- `AProVE/aproveSMT6609298696432134346@2.smt2`

它们的最小化目标在原约束中明确非负，且 OptimathSAT 历史记录标记最优值为 0；
因为另一个对手得到巨大正值而被绝对值规则排除。本轮保留历史集合及记录原样，
把它们作为无法向负方向无界的反例。有限探测结果和未来无界证明应分开统计。

## 14. 基于固定变量和 Z3 LIA 方向查询的无界证明

### 14.1 与有限大目标探测的关系

`--prove-unbounded` 启用独立的补充检测，默认关闭。默认触发阈值为最大化
`obj >= 10^6`、最小化 `obj <= -10^6`；可用 `--unbounded-threshold=M` 调整。
只接受本求解器已经通过 GMP 全公式验算的可行模型，不使用对手的模型或最好值
生成证明。达到阈值只启动检测，本身不表示无界。

每实例进行一次检测，本地调度预算为原生时间限的 5%，最多分配 5 秒，包含在本例时间限内。
预算在循环检查点和 Z3 查询中生效；单次 GMP 运算、Z3 上下文构析和进程调度
不能硬抢占，因此实际检测耗时如实记录，不把少量调度超时当成求解协议错误。
证明完成及接纳仍严格受整个实例的截止时间限制。
检测内部尝试最多八个固定方案；找不到证明、Z3 返回 unknown 或预算耗尽时继续
原优化。证明模式关闭历史 strict-win 早停，以免在启动阈值之前结束。

### 14.2 保留充分的合取分支

对每个硬 CNF 子句至少选择一个在当前模型中为真的文字。保持这些文字同时成立
就足以满足完整 CNF，因此证明这组文字的解集无界足够推出原问题无界。
不能只保留为真的正原子而忽略负文字；布尔门及 ITE 生成的硬子句同样需要覆盖。
所有布尔变量固定在基点的真值，方向为零。

原生算术文字是 `p=0` 或 `p<=0`。正等式保留等式；负不等式在整数域中是
`p>=1`；负等式 `p!=0` 按基点符号选择 `p>=1` 或 `p<=-1`。这样得到一个包含
当前模型且不会越过零点的合取子区域。它可能错过其他无界分支，但不会扩大解集。

### 14.3 精确固定变量并线性化

把选定整数变量固定为当前可行值，将这些值代入所有选中文字和目标。仍未固定的
变量在每个保留单项式中的总次数必须不超过一；否则继续固定变量或放弃该方案。
平方项不能当成线性项；未支持的约束不能删除。系数、固定值的幂、零因子和同类项
合并使用 GMP 精确整数。原搜索为了存储而设置的机器整数范围不属于逻辑约束，
不能据此对数学整数的无界性下结论。

### 14.4 查询整数方向和独立检查

设基点为 `m`。对线性化后的 `a*x+k<=0` 添加方向约束 `a*d<=0`；对等式添加
`a*d=0`。取反的文字按上一节的整数支路添加相应方向约束。固定变量的 `d_i=0`。
目标最大化要求目标斜率至少为 1，最小化要求斜率至多为 -1。

通过已链接的 Z3 C++ API 求解这个 QF_LIA 公式。若返回 SAT，提取任意精度整数
方向 `d`，再使用 GMP 重新检查基点的完整 CNF 可行性、文字覆盖、固定值、
线性化后的导数约束和目标斜率。由此，对每个整数 `t>=0`，`m+t*d` 都满足原生
公式，而且目标趋于相应方向的无穷。Z3 的 SAT 只提供候选方向，精确检查完成且
仍在本例截止时间内才允许报告无界。

### 14.5 输出和证书

证明成功时立即停止，final JSON 保持 `status=sat`、实际有限 `objective_value`
和 `is_optimal=false`，使用 `termination=unbounded_proved`、`is_unbounded=true`。
`time_to_unbounded_seconds` 记录证明完成时间，实验 CSV 的对应时间包括转换耗时。
`unbounded_status` 的 `not_found/unknown/budget` 均不代表已证明有界。

证书为 final JSON 的 `unbounded_certificate` 字段，类型 `lia_ray`、版本 1，保存
原生变量顺序的 `base`、`direction`，固定整数变量索引 `fixed`、覆盖硬子句的
带符号文字 `literals` 和 `objective_slope`。整数保存为精确十进制字符串；布尔
基点用 `1/-1`，方向为零。方向不受 128 位范围限制。证明成功后不再更新基点模型。

`script/verify_optimize.py` 使用 Python 任意精度整数独立重做证书检查，不调用 Z3，
并核对基点与最终模型、结果字段、阈值、证明完成时间及总预算。

后续局部搜索仿射/多项式参数表达式的想法已记录于 [待实现idea.md](待实现idea.md)，
本阶段尚未实现。固定方案或参数模板失败都不能用来证明原问题有界。

### 14.6 验证记录

新增原生方向引擎单测和 8 个原生端到端用例通过，覆盖 min/max、负文字、布尔
分支、负等式、零因子、同类项消除、宽整数、有限大最优值、阈值与默认关闭。
原有优化回归中 23 个通过，1 个可选数据集测试按默认设置跳过。
实验脚本与独立验证器的 105 个测试全部通过；另有两轮只读审查检查数学可靠性、
默认兼容性和时间预算处理。

另对 original 排除集的前 6 个例子做了每例 10 秒、2 并行短测：5 个给出无界
证书，证明完成总时间约 1.18–1.32 秒；另 1 个未获初始解。保留的 5 个模型与
5 个方向证书全部通过不调用 Z3 的独立验证，未启动完整实验。
见 [短测结果](../result/optimize/lia_unbounded_smoke_20261023_01/results.csv) 和

## 15. 目标停滞后调用 Z3 独立检查有限最优

本节描述 2026-10-25 的默认自适应流程。未开启暂停恢复、额外 SLS 窗口和原式初解查询
时仍使用该流程；2026-10-26 的可选扩展及模型记录修复见第 16 节。

### 15.1 触发与调度

`--prove-optimal` 默认关闭。每次接受通过 GMP 完整验算的严格改善模型时，记录
最好值与 `best_time`。当前时间减 `best_time` 达到 `--optimality-stall`（默认 50 秒）
才触发检查。该时钟从首个可行解开始，无可行解时不调用。
同一当前最好值允许重试；每次未证后先回到 SLS，再经过一段无改善期才再次检查。
这与连续改善后尝试无界的触发方向相反，两种功能可并用。

`nia_omt_optimality_schedule.h` 管理自适应预算。`optimality_timeout` 是初始预算，默认
30 秒；首次检查之前的连续改善只重置停滞时钟。一次检查未证后，下一段 SLS 若始终
没有改善，下一次预算为上一轮的两倍；有改善则为上一轮的一半。每个 SLS 阶段最多
减半一次，期间每次改善均重置停滞时钟，避免密集的 incumbent 事件把预算迅速压到底。
SAT 回灌算一次改善。无改善时，等待从检查结束重新计时，保证 SLS 获得完整的 50 秒。
预算下限取 `min(1 秒, 初始预算, 本例总预算)`，上限为本例总预算，实际调用还受剩余时间限制。

父进程暂停搜索，将原式解析、导出查询、Z3 SMT 求解、模型恢复及校验放在 fork 子进程。
子进程重新构造 Z3 context，不复用父进程的 Z3 对象。通过立即 unlink 的临时文件 FD
传递结果，避免大模型写满 pipe 而阻塞。默认未开启 `--optimality-resume` 时，父进程
按墙钟轮询，到期 SIGKILL 并 waitpid 回收；
Z3 内部 timeout 未及时响应也能回到 SLS。只有在子进程结束、结果读取及解码均未超预算
时才接纳证明或模型。匿名结果 FD 不留下临时文件，最近一次实际 SMT 查询仍保留。
批处理外层继续控制整个实例的进程组截止时间；全部开销计入总预算。
未接纳 SAT 模型时搜索继续使用原状态，接纳后从新的最好模型重建搜索状态。
即使预处理消除了全部搜索坐标，也允许等待停滞并检查常量目标。

### 15.2 查询完整原始硬公式

`nia_omt_optimality.cpp` 从 `omt_source` 读取原始 SMT2，核对单个优化目标的方向和
目标表达式与导入元数据一致。过滤输出及求解设置，保留声明、定义和所有硬约束；
不支持的状态修改、多目标或增量查询保守报错。
使用 Z3 Optimize 的解析接口建立 AST，只取完整硬断言和目标，**不执行 Optimize.check**。
随后建立普通 `z3::solver`，加入硬断言与以下严格界：

| 优化方向 | 当前最好值 | 新增硬约束 |
| --- | --- | --- |
| 最小化 | `v` | `obj < v` |
| 最大化 | `v` | `obj > v` |

目标和 `v` 都使用精确整数。保留所有布尔分支；不固定当前模型的变量，
不附加搜索数据结构的 128 位范围。与无界检测不同，缩小解集后证明 UNSAT
不能排除原问题其它分支中存在更好的解，因此不复用固定变量的 LIA 子问题。

### 15.3 接纳条件与结果

若普通 SMT 查询返回 UNSAT，且仍在检查预算和实例总预算内，则不存在严格更优解。
结合原有精确验证的可行模型，确认其目标值最优。原型依赖 Z3 的 UNSAT 结论，
暂不导出或独立重放 Z3 内部证明对象；前端等价性仍沿用现有转换器的假设。
返回 SAT 表示存在更好值，unknown、超时和错误均不表示最优。
SAT 时精确求出原目标值，再由 `nia_omt_model_bridge.cpp` 恢复完整 native 模型：
从原始 AST 收集整数/布尔常量，按原始名称和类型固定 native 中能对应的变量；
为所有 native 变量建立独立新鲜符号，加入完整 native CNF 和目标等于原模型目标值，
调用普通 SMT 补全预处理产生的布尔及算术辅助量。这个补全查询与原始证明查询分离，
补全 UNSAT 只能拒收候选，不能确认原问题最优。

提取的每个整数变量必须能放入 signed128；目标值允许任意宽 GMP 整数。
完整 native 子句和目标在子进程中以 GMP 复验，父进程再次完整验算并调用原 accept
路径写模型、发布 `origin=z3` incumbent。只对真实严格改善增加计数，更新停滞与预算，
重置 SLS 工作状态、plateau 和修复续跑。模型补全失败、变量超界或超时均保留现有最好解，
记录拒收原因；SAT 本身不计 A2。本次不修改 Z3 内部搜索策略。

成功输出 `status=sat`、`termination=optimality_proved`、`is_optimal=true`，
`optimality_proved_value` 必须等于最终经过验证的目标值；无界标志仍为 false。
`optimality_attempts` 与 `optimality_seconds` 是本实例累计次数和耗时，
`optimality_status` 表示最近一次检查状态，`time_to_optimality_seconds` 表示证明完成时间。
`optimality_schedule=adaptive_v1` 标记本节默认调度，`optimality_next_timeout_seconds` 是下次
计划预算，`optimality_sat_models_accepted` 是经过验算并接纳的 SAT 模型数。
Python 将这三列作为可选扩展验证并保存，旧轮结果缺少这些列仍兼容。

Python 独立模式同时禁用历史 strict-win 和已知最优值匹配早停。

## 16. Z3 暂停恢复、搜索窗口与原式初解查询（2026-10-26）

### 16.1 配置与改动范围

这些设置扩展 `--prove-optimal` 的调度，默认保留第 15 节的行为。它们没有修改 SLS
移动、评分、邻域或原问题硬约束，也不使用对手的目标值指导求解或触发证明。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `--optimality-resume` | false | 同一最好值保留并恢复原 Z3 worker。 |
| `--optimality-search-window W` | `0` | `0` 使用原自适应调度；`W>0` 启用短检查、SLS 窗口和长检查。 |
| `--initial-z3-after A` | `0` | `0` 关闭；`A>0` 时允许在无初解且达到触发时间后查询原式可行性。 |
| `--initial-z3-timeout T` | `120` | 可选原式初解查询的预算上限。 |

`W`、`A` 必须有限且非负，`T` 必须有限且为正。暂停恢复、正窗口或非默认初解设置
均要求 `--prove-optimal`。Python Config、CLI、Slurm 冻结配置、manifest 和 summary
传递相同设置；已提交实验使用自己的冻结副本，不随工作区后续修改而改变。
推荐参数依据已完成的6310例单轮实验确定，见16.7；各选项仍保留原默认值，需显式开启。

### 16.2 同值暂停恢复与新值重建

`OmtOptimalitySession` 管理一个原始严格界查询。首次调用 fork worker，由 worker
重新解析完整原式、构造普通 SMT 查询并执行求解。默认未开启 `--optimality-resume`
时，仍调用原来的一次性 `prove_omt_optimality`，每次超时终止并回收 worker。

开启暂停恢复时，一个 slice 到期并不丢弃查询。父进程发送 `SIGSTOP`，再用
`waitpid(..., WUNTRACED)` 等到已停止或已退出的内核状态；确认后才返回 SLS。
因此正常调度返回期间，暂停的 Z3 worker 不继续消耗 CPU。下次目标值和查询输出路径
均相同，发送 `SIGCONT` 恢复原 worker，保留 context、已建立的 AST 和求解状态。
新的 slice 继续从该状态执行，而非重新解析并从头证明。

worker 可在原式解析、求解、模型恢复或结果写出阶段暂停，并保留该阶段的进度。内部不以旧 slice
的墙钟计时使暂停期间过期；外部父进程负责每个 slice 的暂停以及整例截止。
模型桥接使用有限的最大内部预算以兼容其接口，仍处于同一个受父进程监管的 worker
内，并没有因此获得额外实例时间。

SLS 或 Z3 提供严格更好且通过验证的模型时，accept 路径终止并 `waitpid` 回收旧
session，再更新最好值。下次检查为新值建立新的严格界，旧值的结果文件和缓存一起
清除。析构和显式 reset 同样会终止并回收已暂停的 worker。每例最多保留一个这样的
worker；暂停保留其内存，后续是否改善需要结合真实实验中的时间和内存占用评估。

worker 还在 fork 后立即设置 `PR_SET_PDEATHSIG=SIGKILL`，并核对父 PID 与 fork 前
记录的一致。前者处理父进程未执行析构便退出的情况，包括父进程被单独 SIGKILL；
后者覆盖父进程在 fork 和设置信号之间退出的竞态。SIGKILL 能终止已 SIGSTOP 的
worker，不依赖再次恢复它。正常 reset 的 kill/reap 和批处理进程组清理继续保留。

### 16.3 slice、结果缓存与两种预算策略

`W=0` 保留原来的自适应 slice 预算：初始 30 秒，未改善时按 `30→60→120…`
增加，改善后缩短，并受本例剩余时间限制。开启 `--optimality-resume` 只改变查询
是否保留：同值的后续 slice 累积此前 Z3 的工作，而非每次重新创建 context。

`W>0` 保留首次短检查。若返回 `budget/unknown`，先回到 SLS，给出连续的 `W` 秒
窗口；若目标始终没有改善，再进入长检查。长检查取本例剩余时间的 98% 为上限，
保留少量时间输出结果。窗口内改善会重置停滞时钟，并恢复不超过初始预算的短检查。
窗口与暂停恢复是独立配置，可以组合。对于已返回 SAT 的当前严格界，窗口模式和
持久模式不再反复尝试对同一值证明 UNSAT；目标改善后再允许新查询。

父进程读取、解码结果也使用当前 slice 的预算。若 worker 已完成，但结果没有在
slice 内读完，保留 ready 状态供下一次相同目标的有效调用读取；当次只返回 budget，
不会提前接纳。目标或输出路径改变先 reset，因此缓存不能跨到另一个严格界。
无论是否来自缓存，最优性结论仍须在当前调用和本例总预算内被完整接纳。

转换、导入、SLS、初解查询和所有证明 slice 共用每例 1200 秒总墙钟；SLS 窗口及
暂停时间也计入其中，队列等待除外。原生程序在接纳前检查剩余时间，批处理入口
继续对整个进程组执行外部截止。暂停恢复没有扩大时限，也没有把 Z3 耗时移到预算外。

### 16.4 无初解时可选查询完整原式

默认 `--initial-z3-after 0` 不调用此功能，保留原初始化和 SLS 首解流程。可选参数
`--initial-z3-after 300 --initial-z3-timeout 120` 表示：仍无可行解时，在原生计时达到
300 秒后的调度检查点触发一次 `find_omt_feasible`。时间由导入和搜索共同消耗，
触发不是独立线程的精确定时中断；实际预算不超过实例剩余时间。

该查询包含完整原始硬公式，**不加严格改善界，也不调用 Optimize.check**。
原目标只用于从 SAT 模型求出准确的目标值。模型桥接先检查原模型满足原始硬约束，
再补全并 GMP 检查完整 native CNF 和目标；父进程再次完整验算，确认目标与原模型
一致后走普通 accept，发布 `origin=z3_initial` 的 incumbent。SLS 从该模型继续。
原式解析、求解、桥接和结果传递仍由一次性子进程和硬墙钟监管。

SAT 只提供初解，不是 A2；原式硬约束 UNSAT 也不会被误当成“某个可行值已最优”，
该 API 的 `proved` 始终为 false。后续若报告 A2，必须另有正常严格改善查询的 UNSAT。
若启用了无界检测，也只能在独立方向证书校验成功后报告 A1。

### 16.5 截止时刻的模型文件与已发布事件保持一致

原来先原子替换 `model.tsv`，再发布 incumbent JSON。若在两步之间被外部截止，
CSV 只能看到旧目标，而模型文件可能已是更新的目标，导致保留证据不一致。
本次修复只改变模型发布和记录，不改变哪些候选可行、哪些目标更好。

写入新模型前，先以硬链接保留上一代 `model.tsv.prev`，再原子替换当前文件。
每个发布的 incumbent 带当前模型的 `model_inode`。runner 只记住预算内接纳事件
对应的 inode；进程组停止并回收后，在当前文件和上一代中查找它，必要时将上一代
恢复为规范 `model.tsv`。找不到对应文件就明确报错，不声称模型已保留验证。
没有发布的更新模型不会被提升为 CSV 最好值，也不会为它编造找到时间。

模型正文保持原 TSV 格式，原生硬约束和目标的独立验证继续进行。旧程序没有 inode
字段时保持原协议兼容，历史实验原始文件不被修改。这项修复解决模型先覆盖而事件
尚未发布的竞态，没有放宽结果计时或数学验证。

server上完整6310例的复测命令见README；结果继续存到独立的 `NIA_<时间戳>` 目录。

## 18. 临时恢复4.12转换端、证明保留5.1的验证配置（2026-10-27，历史）

交换新旧中间输入，旧输入11～14秒找到解，新输入120秒未找到，说明编码变化

该次验证恢复原来的4.12.3 SDK及原有预处理流水线，没有修改5.1内部化简器来
模拟旧版本。运行库从旧实验冻结的SDK复制到
`competitor/z3-4.12.3-converter/build/{python/z3,libz3.so}`，记录来源和逐文件SHA256；
不依赖fork目录。前端当时检查实际版本为4/12/3，只做解析、tactic和中间格式导出。

原生程序仍链接并检查5.1.0。Slurm将其库复制到 `source/lib`，将转换SDK复制到
`source/converter/z3-4.12.3/build`。Python转换进程显式加载自己的库，之后独立启动
原生进程，避免两种Z3在同一进程混用。历史5.1与fork快照仍按原记录验证。

SAT回灌机制未关闭，也没有在本次恢复中改动。全量日志中严格改善回灌189→245次，

## 19. 同一5.1库中的局部预处理兼容开关（2026-10-27）

## 20. 基于改善反馈的调度与有限覆盖证明（2026-10-28，全量完成）

这次保持SLS邻域、初始化与无界证明算法，改变有限最优查询与SLS之间的信息流。
三个默认关闭的功能分别负责SAT连续改善、有限覆盖证明，以及无产出证明后的搜索窗口。
它们使用同一个本地Z3 5.1库；本轮沿用第19节已统一的前端与算术编码，没有再次修改Z3源码。

### 20.1 一次预算内连续利用SAT模型

旧调度在停滞后检查原式加严格改善界。Z3返回SAT并成功回灌后，重新等待完整的停滞
窗口，才允许下一次查询；快速产生多个改善模型时，这些固定等待会累积。
`--optimality-burst`使一次检查成为一次有共同截止时间的改善阶段：

1. 按现有调度取得预算B，记绝对截止时间d=当前时间+B。
2. 对最小化检查F且obj<M，最大化检查F且obj>M；F保留完整原始布尔结构。
3. SAT模型须通过原始公式、原始目标值以及native约束的精确校验，才能更新M。
4. 若有改善且尚未到d，立刻检查更新后的严格界，预算只剩d-当前时间。
5. UNSAT独立确认当前M最优；未知、超时或无法恢复模型则交还SLS。

同界未完成的worker仍用SIGSTOP/SIGCONT保存状态；更新M会丢弃旧界worker。
这里没有把增量assert后策略切换的Z3与原先tactic混为同一种执行流程，每个新界仍走
已有的完整源查询构造。最终记录、模型校验和写盘接受都检查同一阶段截止时间；
无界证明是返回主循环后的独立阶段，最多仍按原来的5秒预算运行。

预算边界还有一个文件一致性修复：若模型已rename发布，但尚未接受就越过截止时间，
恢复上一个模型文件和inode，避免最终目标值仍属于旧解而model文件已经变成新解。
进程被外部强杀时，仍依赖既有两代inode记录选择与最后有效事件匹配的模型。

### 20.2 从源公式的有限非线性覆盖生成线性分支

`--optimality-cutset`首先查看完整的严格改善公式Q，而不是只看当前赋值满足的文字。
把整数多项式精确展开为GMP系数及单项式；只从无条件成立的合取线性行推导变量上下界。
析取、条件或否定等式下的局部界不能充当全局域。严格整数不等式转换及除法上下取整
保留精确整数语义，例如2x>-7只可推出x>=-3。

选择有限域变量集合C，使每个单项式中未固定变量的剩余总次数至多为1。
例如xy固定一个变量即可，xyz通常须固定两个，xy²仅固定x仍不够。
实现按单项式次数覆盖收益与域宽对数之比贪心选择变量，不按benchmark类别特判。

对每个C的整数赋值a，构造Q[C:=a]，使用线性行传播提前剪掉已矛盾的分支，再检查剩余
公式确实属于QF_LIA，才交给Z3线性整数引擎。返回SAT时显式恢复固定变量的源符号取值，
仍通过既有双重模型校验。只有所有可能分支都已经UNSAT，才宣告Q不可满足。
可靠性依据是Q蕴含C的完整有限域D，因此Q等价于所有Q[C:=a]（a属于D）的析取。
这是源公式蕴含的有限域，不是为搜索方便而增加的人为界。

成本护栏只决定是否采用该路径，不改变证明域：单维宽度筛选、小乘积直接接受，较大
乘积先用线性传播计数，预检限5万叶、20万节点、最多2秒。超限回退原QF_NIA，绝不把
已枚举的前缀当完整覆盖。传播64轮后未收敛只保留已推导的有效界，不推断矛盾。
父进程负责真实切片期限；持久worker内部允许无限预算，以免暂停时间破坏续跑状态。

正确性回归包含高阶乘积、OR局部界、负端点取整、SAT源模型恢复、成本回退和128组独立
小域穷举。测试曾抓到跨叶临时AST数字id被Z3复用造成多项式缓存误用，现每叶清空缓存。

### 20.3 实验与论文表述的边界

首次同293例对照成功数为control50=170、burst50=173、burst10=184；对两个对手逐例
优胜者的负数分别为38、37、31。历史同293例为成功160、负47，但同批control本身也
改善了，因此不能把相对历史的全部变化归因于新调度。这些是前期重点集筛选结果；
后续完整6310例验证已完成，最终结论见20.5，不以重点集结果或条件投影代替全量判断。

60个保留严格界的有限覆盖诊断得到33个UNSAT、1个SAT、26个不适用，无超时或调用错误。
SAT对应旧界cost<273，可行值272在原实验末尾才被接纳，不能误解为推翻最终272最优。
这组诊断不是整轮优化实验，也不能直接把33相加当作全量新增成功数。

有限域分情况线性化已有直接先验：
[Borralleras等，JAR2012](https://www.cs.upc.edu/~erodri/webpage/papers/jar-nia10.pdf)。
严格界驱动非线性优化及增量线性化也已有
[Bigarella等，FroCoS2021](https://es-static.fbk.eu/people/griggio/papers/frocos21.pdf)。
本工作的表述限于具体的OMT协作、预算和精确覆盖实现及其实证效果，不能称为首次混合
SLS/SMT或新的一般NIA完备理论；重点集消融与完整全量结果须分别说明。

### 20.4 无产出证明后的搜索窗口

第一次完整6310例验证得到成功5862、负44，相对历史5798/47为+64/-3。
与同二进制原调度5789/50相比为+73/-6。两轮产物均通过完整模型、事件、预算、ray证书
及有限最优元数据审核；但该中间轮负数减少未达10，因此随后增加了下述balanced调度。

新增的12个负例中，7个original查询不适用有限覆盖，常在同一严格界上累计消耗930秒
而没有SAT；另5个packing的worker卡在有限覆盖内部，没有返回结果。仅按后端是否适用
来决定调度不足以覆盖这两种情况，因而下一步直接利用检查的产出反馈。

`--optimality-balanced`仅在一次严格界检查返回budget或unknown后改变下一次时机。
仍按原方式从本次实际预算b_i倍增得到下一预算b_(i+1)，但下次恢复前给SLS的窗口为

    w_i = max(配置的停滞时间, b_(i+1))。

若期间SLS找到改善值，沿用原来的预算减半和普通停滞时钟重置；若Z3返回SAT并回灌，
仍保留本轮剩余预算内的连续改善；UNSAT仍独立终止。对连续无产出、incumbent不变的
阶段，每个后续证明slice开始之前，SLS已获得至少与该slice计划预算等长的主流程窗口；
若整例先到截止时间，则后续证明不再开始。这是相邻重试的预算契约，不宣称整例SMT
CPU占比恒定50%，也不改变原有初解或无界辅助算子的内部预算。

该开关默认false，要求独立证明，与正search-window互斥。调度变化仅在
`OmtOptimalitySchedule::finished()`的budget/unknown分支；求解公式、源模型验证及
证明接受期限不变。369例保护集合同时覆盖当时全部负例和21个需至少300秒证明的A2，
用于筛选配置并观察追回目标值与损失长证明之间的权衡；最终采用完整6310例实测结果。
