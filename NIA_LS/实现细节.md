# NIA_LS 的 OMT(NIA) 实现细节

本文说明当前 NIA_LS 在 OMT(NIA) 上已经实现的处理。核心流程是：先寻找满足全部
硬约束的可行解，再改进目标；遇到阻碍时，允许扰动当前状态，通过修复寻找更好的
可行解。整个过程中单独保存已经验证的最好解。

原生优化部分对应当前 v15 源码；批处理部分还包括后续加入的完整 bounded
集合选择与“达到对手已证明最优值后停止”规则。

## 1. 问题表示与整体流程

一个实例包含硬约束 `H(x)`、整数目标 `F(x)` 和优化方向 `min` 或 `max`。
优化目标是在满足 `H(x)` 的前提下，使 `F(x)` 尽可能小或尽可能大。

硬约束与目标使用相同的原生变量和单项式，但目标单独存储：

```text
SMT2 文件：硬约束 + minimize/maximize
    ↓ Z3 解析、目标保护和预处理
NIA_LS_OMT 中间格式：变量、单项式、文字、子句、优化方向、目标
    ↓ 原生读取
寻找初始可行解
    ↓ 找到可行解
可行邻域改进 / 中性移动 / 联动修复
    ↔ 扰动后的不可行状态与修复搜索
    ↓ 完整精确校验
保存新的最好可行解及找到它的时间
```

Z3 承担前端解析和预处理。优化搜索使用 NIA_LS 的原生数据结构与搜索模块。
当前实现是有时间预算的启发式搜索，不提供一般的原生最优性证明。

## 2. 输入转换：允许消元，但保住改写后的目标

### 2.1 为什么需要单独保护目标

直接预处理硬约束时，目标变量可能被等式消元。例如：

```smt2
(assert (= cost (* x x)))
(minimize cost)
```

硬约束预处理后，`cost` 可能不再出现在剩余变量中。转换器需要保留的是与原目标
等价的表达式，例如 `x*x`，不要求原变量名 `cost` 始终存在。

### 2.2 使用新鲜标记携带目标

转换器引入一个全新的 `Int -> Bool` 标记函数，把目标放进同一个预处理过程：

```text
硬约束 ∧ marker(cost)
    ↓ simplify / propagate-values / solve-eqs / elim-term-ite 等处理
改写后的硬约束 ∧ marker(x*x)
```

标记函数没有其他用途，其解释可以取为恒真，因此不额外限制原问题的整数赋值。
每个相关阶段检查目标标记是否唯一保留；提取改写后的参数后移除标记，再把硬约束
转为 CNF。标记丢失或重复时明确拒绝转换。

优化方向单独记录，避免最大化目标的符号处理混淆。原始目标文本作为元数据保留，
实际搜索与计值使用改写后的目标。目标中的 ITE 和复杂乘积可以引入辅助变量，
相应定义保留在硬约束中。

### 2.3 原生输入结构

`NIA_LS_OMT 1` 分别记录变量、文字、子句、目标常数与目标项。读取器直接构建
原生索引，避免旧输入路径再次消元、浮点边界换算或系数截断。原有
`best_found_cost` 仍表示未满足硬子句数，实际 OMT 目标由独立的 `omt_*` 字段保存。

目前支持单个非增量整数优化目标及整数多项式、布尔组合、ITE。多目标、量词、
Real、一般 UF、div/mod 等未支持的输入明确拒绝。

对于 Leipzig，批处理转换采用限定的 `--keep-definitions` 策略，保留低次辅助
定义，减少反复代入引起的高次多项式膨胀；其他来源保留默认转换参数。

## 3. 搜索状态：最好解与当前工作状态分开

优化器维护三个相关但不同的状态：

| 状态 | 含义 | 是否允许违反硬约束 |
| --- | --- | --- |
| 当前工作赋值 `state.x` | 用于移动、扰动和修复的探索位置 | 允许 |
| 最好可行赋值 `best` | 已完整校验、目标值最好的已公布结果 | 不允许 |
| 可行代表 `feasible_representative` | 用于继续探索的同目标值可行状态，可承接中性移动 | 不允许 |

暂时破坏当前赋值不会覆盖最好解。只有候选满足全部硬约束，且原目标值严格改善，
才更新最好记录。最小化时要求新值更小，最大化时要求新值更大。

可行中性移动可以更新工作状态和可行代表，但不刷新“找到最好值的时间”。

## 4. 阶段一：优先寻找初始可行解

没有最好可行解时，搜索首先处理违反的硬约束，而不是把不可行状态的目标值当作
有效优化结果。

初始化尝试提供一个完整或部分赋值。已有可行性搜索被封装为可暂停、恢复的
`OmtFeasibilityContinuation`，保留搜索轨迹、缓存、重启状态和独立随机状态。
切片结束后继续原轨迹，避免每次重新初始化、重复搜索同一个前缀。

在初始可行性尝试后，如果仍未获解，就交错执行可行性续跑和原生探索。当前调度
中，初次可行性续跑最多分配约 60 秒且受剩余预算比例限制，后续以约 5 秒切片
继续，中间穿插原生探索。它不会因为最初一段时间没找到解就彻底丢弃首解搜索。

初次可行性续跑可以保留已有的启发式算术路径，产生的赋值只是候选。发布之前仍
须通过完整 GMP 校验；被拒收的候选不能进入最好结果。

## 5. 阶段二：在可行解附近改进目标

### 5.1 面向目标的候选邻域

普通改进步骤优先选择仍满足全部硬约束、并改善当前目标值的候选。邻域包括：

- 单变量局部步长、整数临界点附近值和允许范围端点。
- 二次目标的顶点附近整数，以及投影后目标的二次拟合候选；拟合结果也只作为候选。
- 两变量交换或联合移动，跨过单变量无法改善的状态。
- 面向目标的联合探针，以及目标变量与相关布尔分支的联合变化。
- 宽域变量上的零值和自身最好赋值附近的几何步长探测。

若已经发生一次成功改进，优化器还会沿前后两次已接受赋值的完整差向量作几何
放大，同时重新投影识别到的定义。这可以一次推动多个必须同向变化的坐标。

所有候选都要重新检查约束；二次拟合、外推方向或局部评分本身不保证有效。

### 5.2 可行中性移动

有时必须先改变布局，下一步才有机会降低目标。实现允许在保持可行和目标值不变
的情况下移动，但要求针对目标改进探针的阻碍度严格下降。

中性阶段设有步数上限，并保存同目标值的可行代表，减少平台上的重复往返。
它不发布一个新的最好目标值，也不改变已有最好值的发现时间。

## 6. 阶段三：扰动、修复与自身严格改进界

### 6.1 允许探索暂时不可行的状态

停滞时，优化器可以扰动工作赋值、改变部分目标坐标或分支，再进入修复过程。
最好可行解始终单独保留。

不可行阶段的候选排序使用未满足子句的加权代价和距离等启发式信息；已有最好解
时，还对没有严格改善该值的状态施加虚拟严格界惩罚。约束真值与目标值使用精确
整数，距离与排序中的部分启发式量使用浮点数。

### 6.2 把改进任务转成一个新的可行性任务

假设自己的当前最好目标值为整数 `B`，严格改进条件为：

```text
最小化：H(x) ∧ F(x) <= B - 1
最大化：H(x) ∧ F(x) >= B + 1
```

由于目标是整数，可以用加减一精确表达严格不等式。
`OmtBoundRepair` 重新读入完整原生硬约束，在独立副本上增加这个条件，再用自己的
最好赋值作为修复起点。该条件不写回原始 benchmark。

取得可行解后，这类修复按时间片定期调度。只要自己的最好值不变，修复对象就
继续保存和恢复；最好值改变后，再构造对应的新严格界。修复返回的模型必须同时
通过原约束与严格改进条件的精确检查。

严格界来自 NIA_LS 自己的已验证可行解。修复失败、超时或不支持当前系数范围，
仅表示这次没有返回改善，不表示已经证明严格界不可满足，也不表示最好解已最优。

## 7. 利用约束结构做联动处理

### 7.1 定义等式与条件辅助量

改变一个输入变量后，相关辅助量可能也需要改变。例如目标或硬约束中包含
`aux = ite(g, a, b)` 时，修改影响 `g` 的变量后，旧的 `aux` 值可能立即失效。

实现识别部分单位等式、带守卫的定义，以及唯一、无环的常量条件定义，沿依赖
关系联动更新辅助量。整数等式的求解需要检查整除性，不把非整数结果直接舍入
成一个声称满足等式的值。

当前 v15 将唯一、无环的常量条件定义输出从主要搜索坐标中排除，并把目标优先级
和修复需求追溯到它们的输入变量。完整原生变量和硬约束仍保留。这样减少直接
扰动可由输入确定的辅助量，而不是删除它们对应的约束。

投影有工作上限。常量条件定义中的循环、歧义及其依赖不做坐标消除；无法处理的
投影跳过。投影只是候选生成手段，最终仍检查全部硬约束。

### 7.2 差分约束与析取分支

对于可识别的整数差分约束，可以在固定改进探针后，联动调整一组变量。基本路径
选择当前满足的差分分支，用 GMP Bellman–Ford 处理；扩展路径还可以尝试替换
析取见证，让多个位置一起重排。

图中负环表示当前这组分支选择存在冲突，不能据此断言整个原问题不可满足。
不支持的约束仍留给完整候选验收。

### 7.3 零乘积平台

对于多个因子同时为零的乘积，只移动一个因子可能仍使乘积为零，无法改善约束。
零乘积联合邻域会尝试同时改变多个因子，再检查完整约束，跨过这种单坐标平台。

### 7.4 固定非线性因子，搜索剩余线性问题

`OmtBilinearRepair` 选择一组变量固定为自己的候选值，使剩余多项式尽量成为线性
表达式。例如固定 `x=a`、`z=b` 后，`x*y + z*z` 可以写成 `a*y + b*b`。

双线性二分图结构可交替固定两侧；后续实现还支持部分一般多项式结构，通过固定
高次变量和选择覆盖集合，保证每项最多留下一个一次幂自由变量。

在线性化后，保留完整 CNF 和自身严格改进界，调用本项目的 `LiaSolver` 搜索。
这里使用 Z3 的表达式与模型容器。修复器在切片间保留工作赋值、覆盖集合尝试
进度、中性移动历史和独立随机状态；每次尝试重新构造 `LiaSolver`。返回候选后，
再对原始原生约束与目标进行 GMP 校验。

固定集合、表达式大小、次数与时间都有上限。不支持的情况跳过这个可选算子，
不通过删掉约束、截断多项式或近似系数来构造一个更容易的问题。

## 8. 数值精度与最好解验收

需要区分存储范围、搜索评分和正确性验收：

| 环节 | 当前处理 |
| --- | --- |
| 输入系数、常数、整数变量赋值 | 有符号 128 位整数，超出支持范围时明确处理 |
| 优化主搜索中的多项式真值与目标 | GMP 任意精度整数计算，支持目标结果超过 128 位 |
| 距离、部分排序启发式 | 可以使用浮点数，只用于选择探索方向 |
| 部分固定宽度续跑 | 加入溢出检查；不能继续时结束该次续跑，主搜索继续探索 |
| 发布最好解前 | 从完整赋值独立重算全部原生硬子句和目标 |

最终验收不信任增量缓存和旧算术评分。布尔赋值也要符合原生表示，候选必须满足
全部硬子句，才有资格更新最好解。实现中的有限存储范围和启发式邻域意味着搜索
不完备；不能把没找到更好解解释为已经证明最优。

## 9. 找到什么条件时停止

三类数值在实现中承担不同角色：

| 数值来源 | 用途 |
| --- | --- |
| 自己当前最好可行值 `B` | 生成严格改进界、引导修复 |
| 对手历史最好值，尚未确认最优 | 可选的“严格超过对手后停止”目标 |
| 对手历史中已标记证明最优的值 `x` | 匹配该值后结束本实例 |

### 9.1 可选的严格胜出停止

原生 `--target=<整数>` 只用于判断是否已严格超过该参考值。
它不参与候选生成、初始化、搜索打分或严格界构造。
批处理的 `--no-target` 关闭这条停止规则。

### 9.2 匹配对手已证明的最优值

批处理读取历史 CSV 中 Z3 和 OptiMathSAT 的最好值及 `is_optimal` 标记。若某个
有限整数值 `x` 已标记为最优，则在 NIA_LS 报出经校验、目标值恰好等于 `x` 的
可行解后，脚本可以结束该实例的进程组，保留模型、值和发现时间，再调度下一例。

两个对手的已证明值不一致，或另一个历史可行值已经更好时，该实例不使用这条
提前停止规则。该规则默认开启，指定 `--no-target` 后仍保留；如需禁用，可使用
`--no-known-optimum-stop`。

脚本先接收有效进度，再中断并清理进程组，读取剩余输出；实际报错、异常退出或
清理时出现的目标值矛盾仍如实记录。实际由这条规则中断的实例记为
`termination=known_optimum_reached`。CSV 另保存：

- `known_optimum_value`：已知最优参照值。
- `known_optimum_source`：提供该值的对手。
- `known_optimum_reached`：本次成功保留的最好解是否匹配参照值。

自然结束但数值匹配时，只将匹配字段记为 `true`，保留自然结束的原因。
这里使用的是对手的历史最优性标记，不重新生成或重放对手的 SMT 最优性证明。
NIA_LS 原生输出的 `is_optimal` 仍为 `false`。

## 10. 时间预算、并行与结果保存

完整 bounded 集合的运行命令为：

```bash
cd /home/lbh/OMT
./script/run_optimize.sh all --subset bounded --jobs 180 --timeout 1200 --no-target
```

该命令读取 original 的 3699 例和 new 的 563 例，共 4262 例。
省略 `--subset bounded` 时，仍选择原来的 473 例 `unsolved_bounded_sol` 子集。

最多同时运行 180 个实例任务，每个任务顺序执行转换和原生求解。每例总预算
1200 秒，包括转换、导入、初始化、搜索和验收；排队与启动前的清单扫描不计入
该例预算。正常搜索使用剩余预算，达到已知最优值、预处理矛盾、错误或没有可搜索
变量时可能提前结束。

运行器使用外部截止时间清理进程组，只接收预算内完成验收与保存的最好解。
最好模型先写临时文件，再原子替换；新的最好值及时刷新到 JSONL 日志。
结果中的“找到最好值的时间”是这次严格改进的发现时间，不是实例最终结束时间。

运行开始时复制求解器可执行文件，并在清单中记录二进制与转换器的 SHA256。
各轮从头运行，不把历史结果模型作为新的初始解。结果目录保存 CSV、运行清单、
原生输入、最好模型和日志，便于后续独立审计。

## 11. 独立验证与实验解释

`script/verify_optimize.py` 用 Python 任意精度整数重新检查保留的最终模型、硬约束、
目标、进度、时间与清单。对于已知最优停止，还独立读回历史 CSV，检查参照值、
来源和原始优化方向。它不把运行器声明的匹配标记直接当作验证结论。

这份检查针对转换后的原生公式，不额外证明整个 SMT2 前端转换的等价性；此前未
保留赋值的中间最好解，也只能检查其记录顺序和时间。

当前完整 bounded 实验共 4262 例，4223 例找到可行解，39 例超时未获初解；
3274 例达到对手已证明的最优值，其中 3273 例由匹配规则提前结束。
在原来的 473 例挑战子集上，本轮严格优于逐例更好对手的数量为 326。
历史 v8 单轮最好记录为 330，属于另一冻结版本和运行，不能将两轮成功实例合并。

本轮记录见 [逐例结果](../result/optimize/20261022-085117-434834/results.csv)
和 [独立验证报告](../result/optimize/20261022-085117-434834/verification.json)。
