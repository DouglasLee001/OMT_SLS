## 待尝试的方向

各方向都按通用布尔/算术结构设计，不按cyclic、packing等应用类别或实例名定制。先在未解决实例与已解决回归集上验证，再用同二进制关闭交互的对照和完整测试集验收。

### 1. 恢复006候选，隔离辅助尝试对默认搜索的副作用

**状态：已有候选与小回归，未纳入当前005，未跑完整性能实验。** 辅助convex检查或SMT尝试即使不改变断言，也可能通过同一个context中的AST/搜索状态影响后续默认求解。已有两例受控重放显示，隔离辅助context后，默认UNSAT证明从超时恢复到约4秒。

候选仅将convex分析和SMT预试放入独立context，SAT模型翻回原context并经过原有完整验证；unknown继续原query，所有操作共享总预算。真实Hanoi回归中，旧路径13秒未证，候选约8.24秒完成，包含约5秒预试。这些小例不能外推完整性能。

完整源码、测试、正逆补丁及RED/GREEN保存在 `/data/shared/lbh/OMT/result/NIA_20261030_112517_518871/verification/context-isolation-fix-006/archived-candidate/`。后续若恢复，先复核该目录的 `RESTORE.md`，再单独测试；当前运行命令不会启用006。

### 2. Z3真实分支中的部分赋值 → SLS联合候选

在同一个实际SMT分支中收集已固定的布尔文字、整数值或区间，构成一致的部分赋值，指导SLS一次修改多个相关变量。仅有相位偏好不等于实际赋值，不能拼接不同分支中的通知。

先做只记录、不影响搜索的观察模式，验证变量映射和push/pop后消息撤销。消息携带公式标识、严格目标界epoch和分支revision；过期或矛盾消息直接丢弃。部分赋值仅产生候选，满足全部硬约束且严格改善后才能发布。旧user-propagator候选曾有错误最优结论，不能直接恢复其实现。

### 3. Z3算术冲突、活动度与界 → SLS选择顺序

已有core反馈比较粗；下一步可以记录真实冲突涉及的算术原子、变量活动度及反复出现的界，映射回native变量，调整SLS变量顺序、权重和邻域。

第一步只导出稳定的小统计快照，分别消融“变量优先级”“约束权重”“邻域选择”，避免同时改变所有搜索行为。来自当前分支的界只能作局部提示；只有证明作用域明确的全局有效界才能成为推理约束，不能把局部分支冲突当成原式UNSAT。

### 4. SLS停滞与约束违反信息 → Z3搜索偏好

在当前已验证整数初值之外，提供SLS中长期难修复的约束、频繁共同移动的变量和有效移动方向，作为Z3选择变量、相位或算术初值的软偏好。优先设计有界大小的变量/原子排序接口，先确认后端实际消费，再做性能消融。

SLS统计不是逻辑推论，不能直接写成硬约束或学习子句。重复发送提示也不应重启已经有效的Z3搜索；新目标界与提示更新需分别管理。

### 5. 可恢复SLS会话与Z3增量会话

将SLS提取为可恢复的会话，保存赋值、随机数、惩罚权重、邻域和搜索进度，提供“推进一段时间、提交候选、读取反馈、中断”等接口。Z3会话分别保存原公式、变量映射、当前严格界及证明状态，统一控制器分配总预算。

先缓存解析后的原式及稳定变量映射，减少重复解析；再验证切换时不会重置SLS或错误复用旧目标界。当前子进程暂停/恢复是对照路径，不能仅把两套代码放进同一函数就声称已经共享内部搜索状态。

### 6. 复用有效切线、学习子句和推理界

较容易的起点是跨incumbent保留凸目标的切线支持点：目标与原公式未变时，已有切线仍全局有效；新查询只需更新严格目标界。缓存精确支持点并重新计算切线，不盲信旧系数，证书必须包含全部实际使用的切线。现有proof worker会被新incumbent重置，仅在child里留容器无法实现跨worker复用。

更深的一步是保留Z3学习子句、冲突解释及已证明界。必须区分原hard的全局结论、依赖严格目标界的结论和分支局部结论，保存作用域与变量映射。先在Z3自己的合法增量会话中复用，再研究如何将解释转成SLS可消费的信息；不能把启发式经验包装成引理。

### 7. 可选：利用SMT模型方向生成无界射线候选

两个已验证可行模型可以给出差向量，帮助选择同一射线能够持续满足的文字，减少现有固定变量线性化时选错分支的机会。差向量只是候选，仍须验证所有硬约束沿参数持续成立，且目标沿正确方向无界。

现有native证书验证器要求固定部分变量后残余表达式线性，不是任意多项式射线验证器。先在现有可验证范围内接入模型方向；后续若扩展验证器，需另行实现完整精确验证。当前单次无界尝试、阈值及独立验证协议也要同步考虑，不能把大数或有限外推当成无界证明。

## 历史边界与正确性教训

第一阶段使用 Git 提交 `6614f3c1ea13539918b6f641c64446b753e6db0e` 的搜索和证明逻辑。先把源代码编进统一的 Z3 5.1 可执行文件，再单独研究信息交换的收益。源码集成和信息交换是两项不同的实验，不应混在一次性能比较中。

### 早期接口设计及目前状态

1. **NIA_LS → SMT 的赋值提示（已实现完整整数初值）。** 从经过完整精确校验的 incumbent 导出原变量的赋值，作为可撤销的搜索提示；它不属于原问题硬约束。后续继续完善预处理前后变量、辅助变量和目标表达式的对应关系。
2. **SMT → NIA_LS 的模型。** 严格改善查询返回 SAT 时恢复到 NIA_LS 编码，并用全部原约束与 GMP 精确算术校验；通过之后才更新 incumbent。提交版已经具有该方向的完整模型回灌，后续可以增加局部模型和中间候选，但不能降低校验要求。
3. **SMT → NIA_LS 的冲突与活动信息（已实现core软优先级，活动度仍待尝试）。** 可尝试用冲突涉及的算术原子、变量活动和已证明界来调整局部搜索的选择顺序、权重和邻域。先做只记录的观察模式，再分别开启一种影响，并使用独立消融实验判断收益。
4. **连续求解会话。** 将搜索状态、随机数状态、当前最好模型、证明查询及调度预算分开持有。统一控制器负责暂停和恢复；SLS 不重新调用最外层 OMT 入口。当前提交版用证明子进程的暂停和恢复保留查询状态，不能把它描述为已经实现了同进程的两个可恢复引擎。

## 接入顺序

先确认统一可执行文件相对提交版没有编码和性能退步，再将 proof context 的原公式与变量映射保存在内部对象中，减少序列化和重复解析。之后提取可恢复 SLS 会话，最后逐项接入经过验证的内部信息。优先使用通用算术与布尔结构，不为某个应用类别单独设计规则。
