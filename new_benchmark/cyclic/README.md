## 应用来源与这里处理的问题

本目录复现的是 MiniZinc benchmark 中的 **Resource-Constrained Modulo Scheduling Problem（RCMSP）**：一组任务不断周期性重复，所有任务共用周期；任务之间有依赖，执行时要占用有限的可再生资源。直接依据的模型是本地缓存的 [rcmsp.mzn](../../papers/generate_benchmark/sources/cyclic-rcpsp/rcmsp.mzn)，参数读取和转换实现在 [src/model.py](src/model.py) 的 `parse_dzn()`、`build()` 中。模型的应用背景是循环资源受限调度；这里精确实现的是该 MiniZinc 模型规定的有限整数域和约束。

实例有三种来源，但使用同一套 SMT 编码：

| 文件名前缀 / profile | 数据怎么来 | 是否是新的应用数据 |
| --- | --- | --- |
| `easy_1`、`easy_2`、`medium_1`、`hard_1` / `minizinc` | 读取本地缓存的四份上游 `.dzn`，保留资源、需求和依赖四元组。 | 否，是来源重放。 |
| `tiny-a`、`tiny-b` | 读取交接资料里的手工小例子，用于检查语义。 | 是，规模很小。 |
| `planted-q…-r…-p…-e…-s…` / `planted` | 按参数和随机种子先构造一个可行排程，再由它生成资源和依赖数据。 | 是，是主要的可扩展生成方式。 |

每个实例含 `n` 个任务，编号 `1,…,n`。任务 `1` 是虚拟源点，任务 `n` 是虚拟汇点，持续时间均为 `0`；任务 `2,…,n−1` 是实际任务，持续时间均为 `1`。输入 `requirements[i][r]` 表示任务对资源 `r` 的需求，`capacities[r]` 是资源容量。虚拟任务不计入累计资源使用；若其输入需求非零，代码仍保留原模型中涉及它的成对不重叠约束。

因此，此生成器适用于**单位执行时长、整数时隙的这套 RCMSP 模型**。源码没有一般任意执行时长的输入，也没有把通用 RCPSP 模型自动转换过来。

## 从应用数据到整数变量

每条依赖是四元组 `(i,j,lat,dist)`：`i` 是起始任务，`j` 是目标任务；`lat` 是时间延迟参数，`dist` 是跨迭代距离参数。上游对这类关系的应用解释是：任务 `i` 的某次执行会约束任务 `j` 在相隔 `dist` 次迭代的执行。**实际 SMT 约束使用下一节给出的布尔条件公式**，`lat` 和 `dist` 直接作为有符号整数保留。

先由数据计算一个常量：

```text
U = 所有依赖边的正 latency 之和
  = Σ_(i,j,lat,dist) max(lat, 0)
```

`U` 取自原始 MiniZinc 的 `t_max` 定义，作为模型的有限域上界。它不是随机种子，也不是求解得到的周期。各变量全部声明为 SMT `Int`：

| SMT 符号 | 下标范围 | 含义 | 生成时显式加入的范围 |
| --- | --- | --- | --- |
| `s_i` | `1≤i≤n` | 一个周期内的开始相位；汇点的相位表示周期末端。 | `0≤s_i≤U` |
| `k_i` | `1≤i≤n` | 与任务相位配套的迭代编号。 | `0≤k_i≤n` |
| `T` | 一个 | 公共周期，满足 `T=s_n`。 | `0≤T≤U` |
| `u_i` | `1≤i<n` | 将任务还原到同一迭代坐标的时间 `s_i−k_i*T`。含源点，不含汇点。 | `−n*U≤u_i≤U` |
| `lo`、`hi` | 各一个 | 所有 `u_i` 的最小值、最大值。 | `−n*U≤lo,hi≤U` |
| `C` | 一个 | 单次迭代的跨度 `hi−lo+1`。 | `0≤C≤U` |
| `cost` | 一个 | 要最小化的加权目标 `U*T+C`。 | `0≤cost≤U*(U+1)` |

`u_i` 的界由 `0≤s_i,T≤U`、`0≤k_i≤n` 推得。`C≤U` 则是来源模型本身对 makespan 的限制，转换时照搬。虽然声明给了 `C≥0`，由于 `u_i` 集合非空且 `hi≥lo`，后续等式实际保证 `C≥1`；若某份输入导致 `U=0`，这些约束本身就不可满足，代码不会擅自扩展原域。

## 依赖、周期和资源如何写成 SMT

### 1. 依赖关系：相位条件决定是否加一次迭代

对每条 `(i,j,lat,dist)`，生成：

```text
b_ij = (s_i + lat ≤ s_j)
k_i + ite(b_ij, 0, 1) ≤ k_j + dist
```

当相位满足延迟要求时，左边不增加迭代；不满足时，左边加 `1`，再与右边的迭代编号及给定距离比较。代码直接将条件嵌入 `ite`，不声明额外的 `b_ij` 变量。比如 tiny-a 中的边 `(3,2,1,2)` 写为：

```smt2
(assert (<= (+ k_3 (ite (<= (+ s_3 1) s_2) 0 1)) (+ k_2 2)))
```

这里是严格复现 `rcmsp.mzn` 的 reified precedence。尤其当 `lat` 很大、为负，或 `dist` 为负时，仍只按这个公式处理；源码没有将它替换成含 `dist*T` 的普通经过时间不等式。理解和重建本 benchmark 时应以这条实际约束为准。

### 2. 周期边界与对称性

记持续时间 `d_1=d_n=0`、其余 `d_i=1`。对每个 `i<n` 加入：

```text
s_i + d_i ≤ T
k_n ≥ k_i
```

再加入 `∨_(i<n)(k_n=k_i)`，所以 `k_n` **恰好**是前面所有任务迭代编号的最大值。实际任务只能从 `0,…,T−1` 开始执行，不能跨出周期末端。源点固定 `s_1=0`、`k_1=0`，用于去除整体平移的对称性。`T` 没有被生成参数 `--period` 固定。

### 3. 资源容量：同一整数相位的需求总和

对资源 `r`，取真实任务集合 `R_r={i | 2≤i<n, requirement[i][r]>0}`。如果这些任务的总需求本来就不超过容量，这个资源无需额外累计约束；否则，对集合中的每个任务 `i` 加入：

```text
Σ_(j∈R_r) ite(s_j=s_i, requirement[j][r], 0) ≤ capacity[r]
```

含义是检查所有与 `i` 同相位执行的任务，它们的资源需求之和不能超载。由于真实任务都只执行一个单位时隙、开始时间都是整数，不同相位的执行区间不会相交；任何有负载的时隙也一定是某个任务的开始相位。因此，**逐任务开始相位检查就覆盖了全部可能超载的时隙**，实际生成器没有展开 `t=0,…,U` 的逐时隙大循环。

此外，代码遍历所有任务对 `i<j`；如果某个资源上两者需求和超过容量，就加上来源模型中的冗余非重叠约束：

```text
(s_i+d_i≤s_j) ∨ (s_j+d_j≤s_i)
```

累计约束仍然必要：三个或更多任务可以在任意两者都不超载时，合计超过容量。tiny-a 的两项资源约束就是：

```smt2
(assert (or (<= (+ s_2 1) s_3) (<= (+ s_3 1) s_2)))
(assert (<= (+ (ite (= s_2 s_2) 1 0) (ite (= s_3 s_2) 1 0)) 1))
(assert (<= (+ (ite (= s_2 s_3) 1 0) (ite (= s_3 s_3) 1 0)) 1))
```

## 非线性、跨度与优化目标

周期内相位还不足以计算单次迭代的跨度，因为不同任务可以带不同的 `k_i`。对源点和真实任务加入：

```text
u_i = s_i − k_i*T,  1≤i<n
```

其中 `k_i` 与 `T` 都是未知整数，乘积 `k_i*T` 是本模型真正的整数非线性。源点虽满足 `k_1=0`，真实任务的 `k_i` 仍保留 `0,…,n` 的多值域；生成见证只使用 `0/1` 不会将模型域限制为 `0/1`。

随后用两组包络不等式和两条取值析取实现精确的最大、最小值：

```text
对所有 i<n： hi≥u_i，lo≤u_i
∨_(i<n)(hi=u_i)
∨_(i<n)(lo=u_i)
C = hi−lo+1
cost = U*T+C
```

`hi≥u_i` 配合“至少等于某个 `u_i`”，强制 `hi=max_i u_i`；`lo` 同理。因此 `C` 在每个可行模型中都是实际跨度，并非依赖目标函数才收紧的松弛上界。

最后写出 `(minimize cost)`。在本模型的可行域内，`1≤C≤U`，所以它与“**先最小化 `T`，周期相同时再最小化 `C`**”严格等价：周期多 `1` 的目标增量至少为 `U+1−U=1`；任意跨度改善都不能抵消周期增加。`U*T` 是常量乘变量，属于线性项，非线性来自前面的 `k_i*T`。

所有变量都是整数，所有循环都在 Python 生成阶段展开为有限断言；文件没有量词，也没有实数、浮点数或变量除法。因此声明 `(set-logic QF_NIA)`，并通过单目标 `minimize` 扩展构成 OMT(NIA) 输入。

## 一个可手算的实际实例

完整输入见 [tiny-a--7ceaa9761184.smt2](instance/tiny-a--7ceaa9761184.smt2)，对应原始参数与见证在 [src/case_data/tiny-a--7ceaa9761184](src/case_data/tiny-a--7ceaa9761184)。这是 `n=4` 的例子：两个真实任务 `2,3` 各需要 `1` 单位资源，唯一资源容量为 `1`。依赖是：

| 起点 `i` | 终点 `j` | `lat` | `dist` |
| ---: | ---: | ---: | ---: |
| 1 | 2 | 0 | 0 |
| 2 | 3 | 1 | 0 |
| 3 | 4 | 1 | 0 |
| 3 | 2 | 1 | 2 |

因此 `U=0+1+1+1=3`，`s_i,T∈[0,3]`、`k_i∈[0,4]`、`u_i,lo,hi∈[−12,3]`。取下面的可行解：

```text
s = [0, 0, 1, 2]
k = [0, 0, 1, 1]
T = s_4 = 2
u = [0−0*2, 0−0*2, 1−1*2] = [0, 0, −1]
hi = 0，lo = −1，C = 2
cost = 3*2+2 = 8
```

例如反向边 `(3,2,1,2)` 的相位条件 `1+1≤0` 为假，迭代约束变成 `1+1≤0+2`，恰好成立。该例最后的 SMT 片段为：

```smt2
(assert (= u_2 (- s_2 (* k_2 T))))
(assert (= u_3 (- s_3 (* k_3 T))))
(assert (or (= hi u_1) (= hi u_2) (= hi u_3)))
(assert (or (= lo u_1) (= lo u_2) (= lo u_3)))
(assert (= C (+ (- hi lo) 1)))
(assert (= cost (+ (* 3 T) C)))
(minimize cost)
(check-sat)
```

这里 `8` 也能手工证明最优：两个真实任务在容量 `1` 上不能同相位，所以 `T≥2`；它们在 `[0,T−1]` 内的不同整数相位不可能通过减去整数倍 `T` 变为同一个 `u_i`，所以 `C≥2`。于是 `cost=3*T+C≥8`，上面的解取到下界。[src/test_model.py](src/test_model.py) 中另有对原始有限域的完整枚举检查。`tiny-b` 中记录的 `23` 和 `24` 只是两组见证的比较，不应照此当作最优值。

## planted 新实例如何生成，以及见证代表什么

`src/model.py` 的 `_planted()` 使用 `random.Random(seed)`，过程如下：

1. 设真实任务数为 `q`、资源数为 `nr`、见证周期为 `p`，总任务数 `n=q+2`。令 `baseline=max(2,2*ceil(q/p))`，每个资源容量从 `[baseline,baseline+2]` 随机取整数。真实任务的每种需求从 `0,…,min(2,capacity)` 中取值，并保证每个真实任务至少需要一种资源；虚拟任务需求全为 `0`。
2. 将真实任务逐个放入 `0,…,p−1` 的相位，只接受累计需求不超容量的位置。前两个真实任务分别放在 `0` 和 `p−1`，确保存在严格由晚相位指向早相位的任务对。放置失败时整体重新采样，最多 `64` 次；不会静默修改请求的周期。
3. 从 `1,…,p−1` 选一个切分点 `cut`。见证令 `k_i=1` 当真实任务相位 `s_i≥cut`，否则为 `0`；源点取 `(s,k)=(0,0)`，汇点取 `(p,1)`。
4. 按相位及任务编号排序，连成“源点→所有真实任务→汇点”的骨架链，共 `n−1` 条边。每条边令 `lat=s_j−s_i`、`dist=0`，使相位条件在见证上成立。
5. 再添加 `--extra-edges` 条边，**此数量含第一条必加反向边**。第一条从最晚相位真实任务指向最早相位真实任务；后续随机选择不同真实任务作为端点。每条边随机取 `lat∈[0,p]`，然后按见证计算 `dist=max(0,k_i−k_j+I[s_i+lat>s_j])`。这个值保证该边的实际 `ite` 约束在见证上成立；第一条的 `dist` 为正。随机额外边允许重复。
6. 调用 `check()`，从 `s,k` 独立重算所有依赖、资源负载、周期边界、跨度和目标值，验证见证可行后才写文件。

例如已有文件 [planted-q8-r2-p5-e12-s1002--51912604033c.smt2](instance/planted-q8-r2-p5-e12-s1002--51912604033c.smt2) 有 `8` 个真实任务、`2` 种资源、`p=5`、`12` 条额外边，总依赖数为 `9+12=21`。这份实际数据得到容量 `[6,6]`、`U=29`；保存的见证满足 `T=5`、`lo=−1`、`hi=3`、`C=5`，所以 `cost=29*5+5=150`。模型中 `T` 的域仍是 `[0,29]`，并没有 `(assert (= T 5))`。**见证只保证存在可行解，不保证 `150` 是最优值，也不保证求解器能迅速找到该见证。** 见证不作为额外约束写进实验文件。

生成过程带有“可行排程、排序骨架、必加反向边”的构造偏向。`small/medium/large` 调整的是变量和约束规模，不代表固定求解难度或保证求解成功。

## 生成流水线与源码定位

从上面的生成命令到 `.smt2`，调用顺序是：

```text
src/generate.py
  → 共享 cli.main() / generate_specs()
  → cyclic.model.make()：读取来源数据或构造 planted 数据
  → cyclic.model.build()：声明整数变量并生成约束
  → 共享 core.write_case()：类型检查、见证检查、确定文件标识
  → instance/<参数标签>--<哈希前12位>.smt2
```

共享实现位于 [../packing/src/nia_bench/cli.py](../packing/src/nia_bench/cli.py) 和 [../packing/src/nia_bench/core.py](../packing/src/nia_bench/core.py)。`audit_smt()` 检查逻辑、声明类型和表达式类型；`write_case()` 调用本类 `check()` 复核见证，并在基础约束末尾追加 `(minimize cost)` 与 `(check-sat)`。去重依据规范化应用数据，批量生成只是依次改变种子；标签后的哈希由数据和约束文本共同确定。

`src/case_data/<同名标识>/` 保存生成参数、来源记录、见证等复现资料；实际求解只需要 `instance/` 中对应的一个 `.smt2`，其中已包含全部常量、变量、边界、依赖、资源约束及优化目标，没有外部数据依赖。生成不调用求解器，也不将求解结果混进 `instance/`。
